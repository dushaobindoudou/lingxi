# 把灵犀发布到 WorkBuddy 技能市场

这份文档只讲一件事：**怎么把 `lingxi-desktop-cat` 这个技能包提交到 WorkBuddy 开放平台并上架**。
平台规则以 <https://open.workbuddy.cn/docs/skill> 为准，界面文案可能变，流程不变。

---

## 零、先明确能发什么、不能发什么

WorkBuddy 技能市场接收的是**一个 zip**，里面只能有：

```
{skill-name}/
├── SKILL.md          # 必须
├── references/       # 可选，模型需要时才读的资料
├── scripts/          # 可选，模型用 Bash 调用的脚本
└── templates/        # 可选，模板文件
```

所以灵犀的能力要分成两半看：

| 能力 | 能随技能分发吗 | 说明 |
|---|---|---|
| 模型驱动猫（task / mood / 提醒 / 记忆） | **能** | 就是本包的全部内容 |
| 环境体检（装没装 / 启没启动 / 桥通不通） | **能** | `scripts/check.sh`，只读，不安装不启动 |
| 检测 hooks 装没装、在合适时机提示升级 | **能** | 读 `settings.json` 判断，只读；一场对话最多提一次 |
| 每轮对话自动反应（hooks） | 不能 | 需要写 `~/.workbuddy/settings.json`，只有插件/安装器能做 |
| 带类型的 13 个 MCP 工具 | 不能 | 需要写 `~/.workbuddy/mcp.json` 并由用户点信任 |
| 桌宠应用本体（.app） | 不随包分发，但能代装 | 用户同意后 `scripts/install.sh` 从 GitHub Releases 下载、校验签名并安装 |

**这不是缺陷，是定位。** 技能市场那条路的体验是：
用户装了技能 → 第一次用时模型跑 `check.sh` → 没装就问一句、同意后跑 `install.sh` → 装好后技能立刻生效。

### 没有 hooks，用户会感觉到什么

| 场景 | 有 hooks（插件 / `install.sh`） | 只有技能（市场） |
|---|---|---|
| 每轮开始 | 宿主触发 `UserPromptSubmit` → running，一定发生 | 模型自己判断要不要报，可能不报 |
| 每轮结束 | 宿主触发 `Stop` → completed，模型忘了也有兜底 | 模型报终态，忘了就没有 |
| 权限弹窗 / 提问 | `Notification` / `PermissionRequest` 直接触发 | 覆盖不到，技能看不到宿主弹窗 |
| 失败终止 | `StopFailure` | 模型自己报 `failed` |
| 额度守卫 | 独立 hook 进程读会话用量库，跨 60/70/90% 各说一句 | 没有 |

一句话：**技能给的是"模型想起来时"的反应，hooks 给的是"一定会发生"的反应。**
两者不冲突——装了技能之后仍可跑一次 `install.sh`（幂等）：技能只调 CLI，hooks 只由安装器写，
应用侧对同一事件有让位与去重，不会说两遍。

审核只看包里的内容，**技能不能自带 hooks，也不该在详情页承诺"每轮自动反应"**——
那属于描述与实际不符。

> 另一个硬限制：**灵犀只支持 macOS**。这一点必须写进 description 和详情页，
> 否则 Windows 用户装了用不了，属于"功能描述不实"，是审核驳回的常见原因。

## 一、账号与资质

1. 打开 <https://open.workbuddy.cn/>，点「立即入驻」，用 WorkBuddy 账号登录（会自动关联）。
2. 完成**开发者认证**：
   - 个人认证：可以发布 Skill / 专家 / 连接器。**发技能走这条就够了。**
   - 企业认证：只有发 Buddy 应用、硬件接入才必须。
3. 补齐**开发者信息**（头像、昵称、简介、联系方式）。这一步不做完，最后点「发布」会被拦住——
   很多人卡在这里，以为是审核没过。

`SKILL.md` 里的 `author` 写合作方名称，**建议与开放平台的开发者昵称一致**，否则详情页会显得对不上。
本包目前写的是 `灵犀 Lingxi`，要改就改 frontmatter 后重新打包。

## 二、打包

```bash
cd integrations/hosts/workbuddy/marketplace
./pack.sh            # 官方结构：lingxi-desktop-cat/SKILL.md
./pack.sh --flat     # 备选结构：SKILL.md 直接在 zip 第一层
```

`pack.sh` 会在打包前跑四项校验，任何一项不过就不产出 zip：

| 校验 | 内容 |
|---|---|
| frontmatter | `description` / `description_zh` / `description_en` / `version` / `author` 全部存在 |
| 目录层级 | 不超过两层（`SKILL.md` 一层，`references/x.md` 两层） |
| 体积 | 未压缩 < 3 MB（平台硬限制） |
| 敏感信息 | API key、私钥、cookie、`/Users/<名字>/` 本机路径 |

产物（两个包内容完全相同，只差一层目录）：

| 文件 | 结构 | 什么时候用 |
|---|---|---|
| `dist/lingxi-desktop-cat-v1.0.1.zip`（15.9 KB） | `lingxi-desktop-cat/SKILL.md` | **先传这个** |
| `dist/lingxi-desktop-cat-v1.0.1-flat.zip`（15.7 KB） | `SKILL.md` 在第一层 | 上面那个解析失败时换它 |

同目录的 `avatar-512.jpg` 单独上传（不进 zip）。

### 关于 zip 结构的那个坑

官方文档写的是 `{skill-name}/SKILL.md`，但社区里有多例"按官方结构打包却解析失败"的反馈，
原因是平台解压后对第一层的判断不一致。**先传官方结构；如果报解析失败，再传 `--flat` 版。**
两种包内容完全一致，只是少/多一层目录，不需要改任何文件。

其它会直接导致解析失败的：

- 压缩包里多套了一层（`xxx/lingxi-desktop-cat/SKILL.md`）
- 目录深度到三层（`references/sub/a.md`）
- frontmatter 缺 `description_zh` / `description_en` / `version` / `author` 任意一个
- frontmatter 没用 `---` 闭合，或 `---` 前有空行

## 三、提交

平台路径：**发布管理 → 技能 → 右上角「创建」**。

| 步骤 | 做什么 | 注意 |
|---|---|---|
| 1 配置技能 | 拖入 zip，平台自动解包解析并生成技能 ID | 只支持 `.zip`，≤ 3 MB |
| 2 确认信息 | 核对解析出的名称、版本、简介；补市场展示分类、服务类目、头像 | **解析出来的字段在页面上改不了**，写错了要回 SKILL.md 改完重传 |
| 3 提交审核 | 核对汇总页，点「提交」 | 提交后状态是「待审核」 |

### 可以直接抄的填写内容

**市场展示名称**：`灵犀桌宠`

**一句话介绍（详情页首行）**：

> 让桌面上的 3D 小猫替你传达任务的开始、结果、失败和等待，并按内容判断心情。需要灵犀 macOS 应用，没装时经你同意可一键安装。

**详细介绍**：

> 灵犀是一只住在 macOS 桌面上的 3D 小猫。装上这个技能后，WorkBuddy 在干活时可以让它作出反应：
> 任务完成时一起得意，失败时凑过来接住你，需要你确认时抬头提醒你，深夜连着干活时打个哈欠催你休息。
>
> 和普通通知的区别在于「心情」：技能会让模型判断这件事是得意、温柔、挫败、担心还是疲惫，
> 猫再决定怎么回应——失败得到的是安慰，不是又一条红色警告。
>
> 它还能替你放心上该提醒的事（「45 分钟后起来走走」「每天 09:30 站会」），
> 并记住一些关于你的、具体的观察。
>
> **使用前需要**：macOS 12 及以上，以及灵犀桌面应用（免费）。
> 技能首次使用会做一次**只读体检**；发现没装时会先问你，**你同意后**才从 GitHub Releases 下载最新版，
> 校验 SHA256 与代码签名后装进「应用程序」并打开，不对就拒装。它不会改 WorkBuddy 的任何配置。

**市场展示分类**（可多选）：`效率工具`、`桌面与系统`

**服务类目**（1–5 个）：`工具-办公`

**头像**：上传 `avatar-512.jpg`（512×512，44 KB，符合"JPG/PNG，≤500KB"）

**试试这样问我**（如果有这个输入项）：

- 让猫知道我这一轮在做什么
- 任务完成了，让猫表示一下
- 45 分钟后提醒我起来走走

### 审核

- 官方口径约 **7 个工作日**，实测多在 **1–3 天**；结果在开放平台「通知中心」，
  同一微信号也会收到 WorkBuddy 消息中心通知。
- 常见驳回原因，按概率排序：
  1. **描述与实际能力不符**（例如暗示能自动反应，但技能做不到）→ 本包已把能力边界写清
  2. **description 没有触发词**，模型不会调用 → 本包已列中英文触发词
  3. **未声明平台限制** → 已在 description 与详情页写明 macOS
  4. 含外部下载/执行行为 → 本包只在用户同意后下载**灵犀自己的 release**（固定仓库、校验 SHA256 /
     bundle id / 代码签名），不执行下载来的脚本，不改宿主配置；详情页与 description 已如实写明。
     审核若仍以此驳回，在申诉里附上 `scripts/install-app.sh` 的校验逻辑说明
  5. 目录/字段不合规 → `pack.sh` 已拦住

## 四、发布（最容易被漏掉的一步）

**审核通过 ≠ 上架。** 状态会变成「待发布」，必须回到 **发布管理 → 技能**，点右侧「发布」，
选择发布方式：

- **公开发布**：所有 WorkBuddy 用户都能在市场搜到、安装 → 选这个。
- **专用发布**：只在自己账号下的 Buddy 应用里可见。

点确定后状态变「已发布 · 公开」。到这一步才真正能被搜到。

---

## 五、上架后验证

在 WorkBuddy 里走一遍真实用户路径：

1. 左侧「专家 · 技能 · 连接器」→「技能」→ 技能市场，搜「灵犀」，确认能搜到。
2. 点右上角加号安装 → 详情页出现「去试试」。
3. 开一个新会话，**不要提技能名**，用自然语言试：
   - 「这一轮在改登录页，让猫知道我开始了」
   - 「测试全过了，让猫高兴一下」
   - 「45 分钟后提醒我起来走走」
4. 用 `bash <技能目录>/scripts/lingxi.sh state` 看 `expression` / `intent` 是否变化。
5. 验「没装应用」的提示，**不要真去卸载**，用隔离环境模拟：
   ```bash
   HOME=/tmp/lx-fake LINGXI_APP_DIRS=/tmp/lx-empty PATH=/usr/bin:/bin \
     bash <技能目录>/scripts/check.sh          # 期望 RESULT: app-missing
   HOME=/tmp/lx-fake LINGXI_APP_DIRS=/Applications \
     bash <技能目录>/scripts/check.sh          # 期望 RESULT: app-not-started
   ```

## 六、版本迭代

- 改内容 → 改 `SKILL.md` 的 `version` → 重新 `./pack.sh` → 后台「更新版本」上传。
- 用语义化版本：文案/触发词调整升 patch，新增能力升 minor，结构变更升 major。
- 下架/设置都在同一张卡片的「设置」「下架」里。

---

## 七、两条分发路径怎么选

| | 技能市场（本包） | 插件 + 安装器（`install.sh`） |
|---|---|---|
| 用户动作 | 市场里点安装 | 跑一条 shell 命令 |
| 自动反应（hooks） | 没有 | 有 |
| MCP 13 工具 | 没有 | 有（需点信任） |
| 应用安装 | 模型问一句，同意后代装 | 会话开始时自动下载安装 |
| 审核 | 要过平台审核 | 不需要 |
| 适合 | 普通用户、想一键试 | 重度用户、要完整接入 |

**共存不会双发**：技能只调用 CLI，不注册 hooks；hooks 只由安装器写。

## 八、提交前自检清单

- [ ] `./pack.sh` 四项校验全绿
- [ ] zip 内第一层是 `lingxi-desktop-cat/`（或 `--flat` 版的 `SKILL.md`），没有多套一层
- [ ] `SKILL.md` 的 `version` 与准备填的版本号一致
- [ ] `author` 与开放平台开发者昵称一致
- [ ] 头像 `avatar-512.jpg` 已准备（512×512，≤500KB）
- [ ] 详情页写明了「需要灵犀 macOS 应用，经同意可代为安装」
- [ ] 开发者信息四项（头像/昵称/简介/联系方式）已补齐——否则发布会卡住
- [ ] `check.sh` 三种结论都验过：真实环境 `ready`、模拟 `app-missing`、模拟 `app-not-started`
- [ ] 在一台没装灵犀的 Mac（或删掉应用后）走一遍：问一句 → 同意 → `install.sh` 装好并打开
- [ ] 提交后记得回来点「发布」，不要停在「待发布」
