## 1. 问题说明

### P1 样式：边框太粗、字体太大（已修，待纳入基线）

气泡实际观感由两层叠加决定，此前两层都在往"漫画风"加码：

| 层 | 位置 | 此前 | 问题 |
|---|---|---|---|
| 内置默认 | `stage-fx.ts` `DEFAULT_BUBBLE_STYLE` | 2.5px 近黑描边、15px/600、硬投影、弹簧过冲入场 | 系统腔的重 |
| 用户资产 | `assets/bubble.json` | 3px 亮青 `#0AC89F` + 16px + 硬投影 | 直接触发抱怨 |

已改为治愈系基线（明细见附录 A）：1px 暖灰发丝边框、13px/500、暖白底、柔和弥散阴影（spiky 爆炸框保留硬投影，喊话该有冲击力）、行高 1.6、轻柔入场。**请 app 侧复核后随统一优化一并提交。**

### P2 未读与遗忘：说完即死，没有"还记得"的形态

气泡生命周期：`hold = min(9000, 1800 + len×130) ms`，全屏一次只一条，后条顶前条。由此产生两个失败模式：

- **A 没看到**：用户 AFK、或完成气泡被后续事件顶掉 → 完成消息彻底丢失，事后猫不再提。
- **B 看到但忘了**：气泡显示过、随即消失，没有存档入口，没有"有 N 件事没读"的持续状态。

关键分级（本方案的分界线）：

| 未读类型 | 例子 | 遗忘成本 | 对策 |
|---|---|---|---|
| 完成态 | completed / cancelled | ≈0，活儿已干完 | **可查**：面板存档 + 回来补说摘要 |
| 待办态 | needs_approval / needs_input / failed / blocked | 真：流程卡在用户手里 | **被记得**：猫身上的持续标记 |

全量挂未读点会把猫变成第二个通知中心，违背治愈系定位。

### P3 文案：长度与信息量的双重失配

- **太长看不完**：不是错觉，是数学（§3.2）。140 字截断 + 9 秒封顶，长句必然被"处决"。
- **太短不知道说什么**：无主语无宾语（"做完了"——什么做完了？），或系统腔（"任务 #123 状态变更为已完成"）。

## 2. 未读方案（app 侧主体）

### 2.1 状态机

```
task-event 送达
  ├─ 气泡渲染时用户 active（读 idle 信号）→ seen，流程结束
  └─ 用户 idle/dormant，或被后条顶掉      → unseen
unseen → acked：点猫回放 / 打开面板 / 回来摘要送达
unseen 超 24h → 降级纯存档（猫放手，面板仍可查）
```

- idle 信号已存在：`PerceptionSnapshot.idleMs`（`packages/perception-contract/index.d.ts:36`），活动原子量 0=active / 1=idle / 2=dormant（`lib.rs:4540`）。
- seen 阈值建议：气泡渲染时 `idleMs < 45_000` 记 seen；具体数值 app 侧用真实数据调。
- 未读状态建议作为**任务行的属性**存在 app 侧（任务行本就由 task-event 创建），插件不自建未读账本。

### 2.2 表达语言

- **待办态未读**：猫头顶小圆点 + 数字（游戏 quest marker 的治愈化）——奶油底、品牌色细描边、呼吸式缓动 3–4s 周期；绝不闪烁、不用红色；`9+` 封顶。
- **完成态未读**：不挂标记。由插件侧回来摘要（§2.3）+ 面板存档承接。
- **可选身体语言**：耳朵朝前、偶尔看向用户（`reactions.json` 是配置资产，但"未读态→表情"触发逻辑在 app 侧）。
- **面板**：任务行加未读点；打开面板即全部 acked。

### 2.3 手势槽

现有语义（`main.ts`）：拖拽 = 拿起挪位；双击 = 打招呼（顶头 + 爱心 + 一句话，`main.ts:536`）；单击目前只记录 `click_on_pet`，**是空槽**。

建议：单击时若有待办态未读 → 回放一条（复用现有气泡 + 出处行，逐条消费）；无未读 → 保持现有撸猫反应。双击不动。

### 2.4 分工边界

| 工作 | 归属 |
|---|---|
| idle 门控 + 回来摘要（dsh 事件先行版） | **插件侧**（dsh-lingxi，已计划，见 §5） |
| 未读小圆点渲染 | app 侧（`stage-fx.ts` fx 层，锚点复用 bubble 的 tracking） |
| 单击回放分支 | app 侧（`main.ts` 点击处理） |
| seen 判定（渲染时读 idle） | app 侧 |
| 面板未读点 + 打开即清 | app 侧（`management.*`） |

## 3. 文案方案：一条气泡一口气

用户原话是标尺：**"既不能是一大段看不完就消失了，也不能太短不知道表达什么意思。跟正常一个朋友一样，简单明了直白可以有情绪。"**

### 3.1 朋友腔五原则

1. **结论先行**：前 5 个字必须给出结果或状态（"修好了""卡住了""差你一步"）。
2. **具体名词**：说"typert 的 404"，不说"构建任务"；名字是共同记忆，抽象名词是噪音。
3. **情绪跟事实匹配**：task-event 已带 9 档 mood（focused/proud/tender/sad/frustrated/anxious/weary/playful/curious）。赢了可以说"成了，一次过"；磨了三轮就说"磨了三轮总算绿了"。但不许每句都兴奋——情绪通胀等于没有情绪。
4. **一条只说一件事**：第二件事是下一条气泡，或摘要行里的一顿号。
5. **待办必带下一步**：差什么 + 用户要做什么（"差你一步：命令要你点头"）。失败句用第一人称视角（"我卡住了"），不指责用户（"你的命令失败了"）。

短句（≤8 字）只有在**共同语境**刚建立时才允许用（用户刚盯着你修完某事，"成了"是成立的）；agent 主动播报必须带名词。

### 3.2 长度数学（为什么 27 字是生死线）

- 气泡存活：`hold(L) = 1.8 + 0.13L` 秒（9s 封顶）。
- 舒适阅读：`need(L) = 0.8（注意到）+ L/6（中文 ≈6 字/秒）`秒。
- 盈亏点：`L ≈ 27`。此后 hold < need，**"看不完就消失"是必然，不是错觉**。
- 实测对照：40 字（13px、280px 宽下约 2 行）需 7.5s，只给 7.0s；60 字需 10.8s，只给 9.0s。

长度阶梯：

| 长度 | 定位 |
|---|---|
| ≤8 字 | 状态点缀，仅在共同语境下使用 |
| **12–25 字** | **甜点区，默认目标** |
| 26–40 字 | 上限，两行内 |
| >40 字 | 不许上气泡：拆分成多条，或面板行 + 短气泡引用 |

### 3.3 hold 公式建议

按行数而非字数计（行数才反映真实排版，13px/280px ≈ 21 字/行）：

```
hold = clamp(1.2s + 行数 × 2.2s, 3.2s, 12s)；alert 档（待办类）下限 6s
带出处行（logo + agent 名）时 +0.5s
```

防遗忘不靠拉长 hold（那是煎熬），靠 §2 的未读机制；hold 只需保证"第一遍能读完"。

### 3.4 例句库

| 档位 | 反例（系统腔） | 正例（朋友腔） |
|---|---|---|
| queued | 已加入任务队列 | 收到，记下了：帮你盯着 12306 |
| running | 任务正在执行中 | 在跑 typert 的测试，好了叫你 |
| completed | 任务已成功完成 | typert 的 404 修好了，全绿 |
| completed·proud | 构建流程执行完毕 | 成了，一次过 |
| completed·weary | 任务已完成 | 磨了三轮，总算绿了 |
| failed | 执行失败，退出码 1 | 卡住了：flaky 测试第三次超时，现场我先留着 |
| needs_approval | 等待用户授权 | 差你一步：要跑的命令需要你点头 |
| needs_input | 等待用户输入 | 想跟你确认个事：A 还是 B？ |
| 回来摘要（3 件） | 完成 3 项任务 | 刚才三件事都齐了：404 修好、发版打包完、记忆整理完 |

规则：一条气泡最多 1 个数字，且数字必须是结论的一部分（"142 个测试全绿" ✓，"耗时 3 分 24 秒完成 142 个用例" ✗——后者进面板）。

### 3.5 反模式清单

- 一段 >40 字；数字堆砌（百分比 / 耗时 / 任务 ID 全上）。
- 系统腔名词：'任务''执行''状态变更''成功完成'。
- emoji 轰炸（至多一个，治愈系靠语气不靠表情包）。
- 无主语短句主动播报（"做完了"）。
- 每次完成都是长句（去重已有 per-(task,state)，档位也要跟：同一任务第二次播报应更短）。

## 4. 验收标准

1. 任意 say ≤ 2 行且 ≤ 40 字（插件 smoke 可加断言；app 侧对超长做拆分或降级面板 + 短引用）。
2. AFK 期间的完成事件，用户回到 active 后以摘要形式**出现一次且仅一次**。
3. 待办态未读：猫身上可见 → 点猫必达 → acked 即消失；24h 后自动放手。
4. 样式基线统一为附录 A（1px / 13px / 柔和阴影 / 行高 1.6）。
5. 双击打招呼、拖拽搬运语义不变；单击在无未读时行为与现状一致。

## 5. 与插件侧的接口

**插件侧已计划（不需要 app 改动）**：dsh-lingxi 的 `notify.js` 在发完成档 say 前查 `GET /perception` 的 `idleMs`：用户 active → 照发；idle/dormant → 攒住，回到 active 后发一条合并摘要（ladder 与 per-(task,state) 去重挂钩现成）。

**开放决策（请 app 侧定夺）**：

1. 摘要归谁：插件摘要只覆盖 dsh 事件，先行可用；建议长期由 app 统一摘要（覆盖所有 agent），插件方案作为兜底。若 app 侧接手，插件撤掉自家摘要逻辑。
2. 未读状态归属：建议 app 侧任务行持有（§2.1），插件不自建账本。
3. 手势地图：单击回放 / 双击打招呼 / 拖拽搬运已占满，后续若要"单击开面板"需先全局重排。
