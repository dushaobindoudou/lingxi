## 1. 角色身份

| 项目 | 原始方向 | 生产时需要补齐 |
| --- | --- | --- |
| 名字 | 陪陪 / Peipei | 与项目名称的关系 |
| 年龄感 | 3～6 个月幼猫，不过度幼儿化 | 通过统一比例图确认 |
| 风格 | 风格化真实主义，原文约 80% 真实、20% 风格化 | 作为美术描述，不作为测量指标 |
| 轮廓 | 头略大、身体圆润柔软、爪子圆 | 正交视图与统一长度基准 |
| 毛色 | 暖白主体、浅灰棕虎斑、淡粉鼻耳 | 色板、左右花纹与背尾分区 |
| 眼睛 | 灰绿或琥珀绿、湿润、不过度放大 | 二选一并固定虹膜与反光风格 |
| 性格 | 温柔、独立、懒散、适度好奇 | 身体的脾气，见 `presets/personalities/`。数值是倾向，不是日程 |
| 自我 | 猫朋友。朋友与猫是天性，人在场时朋友更强，人离开时它就是猫 | 见 [决策 004](decisions/004-cat-friend.md)。引擎尚未消费这段身份 |

它是猫朋友。人离开时它过自己的一天。人在场时它认得你，记得一起待过的场面，对得上就会在相近的时候出现。它能帮你，是因为它在，不是因为它值班。对不上任何场面，它也可以做自己的事，或者不过来。开口很少。换了角色，脾气可以变，这段关系留在这只猫身上。

朋友与猫的比重是天性：两边冲突时谁让步。它正睡着，朋友让；你在，而且这件事里有过它，猫的身体仍可以不过来。一天里多少时间像朋友、多少时间像猫，是过完才看得到的结果，不是目标，也不写进性格滑杆。

“奶油虎斑”暂作工作描述，以最终色板和花纹图为准。头和眼睛增大 10%～15%只作为探索起点，须说明相对哪张基础参考，不能脱离基准直接建模。

## 2. 第一份正式交付：角色参考包

需要正面、左侧、右侧、背面、俯视、四分之三视角，以及脸、眼、鼻、耳、爪垫、尾巴和毛流细节。正交视图保持同一中立姿态、比例、地面线和光照；四分之三视图只用于外观检查，不承担尺寸标注。

交付中必须有：统一尺寸基准、身体与尾长比例、左右花纹图、色板、毛长分区、毛流方向、认可版本与变更记录。角色可以天然不对称，不应为省工把左右花纹强行镜像。

AI 多视图是候选参考，不能自动保证几何一致。先人工对齐眼位、耳位、四肢长度、尾根和花纹；通过后才用于建模。当前概念板可作为审美参考，但尚未形成生产用多视图，本轮仅定义交付规范。

## 3. 生产流程与质量关卡

| 阶段 | 输入与产物 | 进入下一阶段的条件 |
| --- | --- | --- |
| 概念冻结 | 概念候选 → 角色参考包 | 各视角身份一致，关键外观有明确依据 |
| 基础模型 | 参考包 → 人工或 AI 辅助 blockout | 比例、轮廓、四肢分离、尾根正确 |
| 清理与拓扑 | blockout → 可变形网格、UV | 肩髋、眼睑、尾根可弯曲，无明显破面 |
| 材质毛发 | 网格 → 美术母版 | 小尺寸下仍能看清眼睛与毛茸茸轮廓 |
| 绑定 | 模型 → 可复用控制骨架 | 趴、睡、抬头姿势无明显穿插与塌陷 |
| 动画 | 骨架 → 循环片段与过渡片段 | 所有入口出口姿态可连接 |
| 运行时产物 | 母版 → 透明序列或实时模型 | 在目标应用内通过视觉和性能检查 |

Blender 是原材料提出的核心候选工具；Meshy / Tripo 仅作为可选的初始模型来源，本轮未评测其当前质量、价格或授权。是否采用取决于清理所需时间是否低于直接建模。无需依赖 AI 四足动作捕捉来完成首个闭环。

## 4. 两种资产用途

**美术母版**保存完整模型、材质、毛发、绑定与动画，用于离线渲染与后续修改。

**运行时产物**由选定路线决定：预渲染路线交付透明帧或经验证的透明编码；实时路线交付网格、贴图、骨骼与烘焙动画，例如 GLB。不要假设美术软件中的毛发、约束与节点材质能直接保真进入运行时，必须用样片导出验证。

原文的 50～80 根骨骼只是预算候选；控制骨与导出骨应分别统计。毛发等级按屏幕投影尺寸和设备负载选择，不直接照搬游戏中的摄像机距离。

## 5. 首批动作交付

P0 建议使用 6 个具名片段，先让一个姿态闭环成立：

| ID | 内容 | 入口 → 出口 | 播放约束 |
| --- | --- | --- | --- |
| `rest_loop` | 趴着呼吸，含自然微动作 | rest → rest | 循环，标注安全切出点 |
| `rest_to_sleep` | 放低头、闭眼 | rest → sleep | 过渡播完再进入睡眠 |
| `sleep_loop` | 睡眠呼吸与轻微耳动 | sleep → sleep | 循环，标注安全切出点 |
| `sleep_to_rest` | 醒来抬头 | sleep → rest | 不从深睡直接跳到注视 |
| `rest_look` | 有限方向注视再收回 | rest → rest | 可增加左、右变体，不承诺任意角度 |
| `rest_pet` | 头部抚摸反应 | rest → rest | 有冷却，不能连续重启动画 |

这里是 6 个片段，不是 6 个产品状态。M1 按反馈增加变体、洗脸和伸懒腰。移动必须另有行走与落位过渡；不能仅平移趴着的图像来冒充行走。

原始 25 项动作池保留如下：1 趴着发呆、2 坐着发呆、3 看窗外、4 舔爪、5 洗脸、6 整理毛发、7 普通睡觉、8 蜷睡、9 趴睡、10 翻身、11 伸爪、12 睡梦微动、13 看鼠标、14 追鼠标、15 扑鼠标、16 靠近、17 蹭窗口、18 被摸、19 好奇、20 开心、21 困、22 委屈、23 不想理你、24 想陪你、25 伸懒腰。19～24 主要是表现目标，需拆成实际动作；14～17 涉及额外运动和桌面能力，不直接算首版已承诺交付。

## 6. 每份动画的交付信息

记录 `id`、角色版本、入口/出口姿态、时长、帧率、画幅、循环点、安全切出点、视觉朝向、地面锚点、活动包围盒、交互区域、位移方式与适用情绪。预渲染素材还需标注 alpha 方式、色彩空间和各帧偏移；实时素材需标注动画名称和导出骨架版本。

预渲染片段保持相同摄像机、比例、曝光、地面位置和透明处理。交叉淡化仅能处理少量兼容姿态，不能替代睡觉到坐起的真实过渡，否则容易出现双重轮廓。

建议资产布局（尚未创建资产）：

```text
assets/peipei/
  reference/       # 冻结的角色视图、色板、尺寸
  source/          # Blender 母版及依赖
  textures/        # 贴图
  animation/       # 动作表与源动画
  runtime/        # 选定路线的交付产物
  manifests/      # 版本、片段元数据与授权来源
```

每项外部素材记录作者、来源、获取日期、使用范围及原始文件；具体商业授权在采购前核对。验收应同时看目标桌面尺寸与放大视图，避免只在宣传大图中成立。
