# 项目理解与分析

> 历史基线（2026-09-10）：产品现已命名「灵犀」，用户要求以真实实时 3D 为目标。最新决定见 [实时 3D 决策](decisions/001-realtime-desktop.md)、[品牌设计](08-brand-and-design-system.md)和[扩展架构](09-extension-architecture.md)。与新决定冲突的旧建议不再适用。

## 1. 项目的核心

陪陪的价值在于：用户不必持续输入、照料或对话，也能感受到一个熟悉的小生命陪在身边。形象稳定让用户认出“我的猫”，运动自然让用户愿意看，行为连续让关系能够积累。

从材料中可以提炼出四条原始方向：

1. **同一只猫**：脸、花纹、比例和气质跨动作保持一致。
2. **安静陪伴**：大多数时候睡觉、发呆、整理自己；用户掌握互动强度。
3. **有自主性**：会忽略刺激、失去兴趣、换姿势，行为有上下文。
4. **长期连续性**：重新打开仍然是熟悉的陪陪，关系不依赖每次重新聊天。

“数字生命”在这里是体验目标，不表示产品拥有意识或真实情感。“担心用户”应实现为克制的行为表达，而非声称系统准确识别了用户心理状态。

## 2. 用户与价值假设

建议优先验证长时间在电脑前工作或学习、喜欢猫、愿意接受桌面常驻角色的人。尚无用户访谈、需求规模、竞品研究或付费数据支持，不能把目标人群描述当作市场结论。

核心使用任务是：“我独自工作时，希望身边有点温暖和生命感，但不想再多一个需要照顾的任务。”

需要验证的不是用户是否觉得图片可爱，而是他们是否愿意让它持续留在桌面，并在一周后仍然主动打开。

## 3. 产品能力的关系

| 层次 | 作用 | 失败时的体验 |
| --- | --- | --- |
| 角色身份 | 外形、花纹和人格边界稳定 | 像不断换猫 |
| 视觉 | 柔软的轮廓、毛发、眼睛、光影 | 像普通模型 |
| 运动 | 呼吸、重心、注视延迟、自然过渡 | 像机械动画 |
| 行为 | 作息、冷却、偏好、自主选择 | 像固定循环 |
| 桌面共存 | 不抢焦点、可穿透、可隐藏、节能 | 妨碍工作，被关闭 |
| 长期关系 | 记住位置、偏好与少量互动 | 每次都像首次使用 |

材料把 Cat Life Engine 视为壁垒。这是有价值的方向，但壁垒仍需通过行为调校、资产质量和长期使用反馈积累，不能由架构图直接证明。

## 4. 原始材料需要修正的地方

| 原始表述或分歧 | 分析与整理结论 |
| --- | --- |
| 前面推荐全实时 Groom，后面推荐预渲染，再提出身体预渲染、眼耳尾实时 | 这是三条不同复杂度的路线。先做对照样片，不能把三者叠加当作低成本默认方案。 |
| 预渲染加状态图就不会像 GIF | 状态图只解决顺序。片段变体、接缝、持续时间和上下文共同决定循环感。 |
| 预渲染身体之上实时转头、耳朵和尾巴 | 普通扁平帧没有可独立控制的骨骼。需要分层、遮挡与光照匹配，或切换到实时模型。 |
| 5 个核心状态、20 或 25 个动作、另加 20 个变体 | 状态与动作不是同一单位。建议先做最小闭环，25 项作为扩展动作池。 |
| “开心、委屈、想陪你”列为动作 | 这些是情绪或意图，应映射到姿态和动作组合。 |
| 不看鼠标 40%，另一处又是 20% | 不采用冲突的固定概率；由当前状态、注意力预算和冷却决定。 |
| AI 完成 50%、视觉 95%、性能 90%、毛发贡献 30% | 没有测量依据，不进入工程验收标准。 |
| 头、身体、腿、尾巴加起来 100% | 测量口径不明确，不能用于建模；改为带尺寸基准的角色参考图。 |
| 四周完成高质量角色及应用 | 可作为原始愿望保留，正式工期需看美术能力、资产来源与样片结果。 |
| CPU/GPU 极低且电影级毛发 | 都是愿望，需要在指定机器、画面尺寸与帧率下共同验证。 |

## 5. 建议的收敛

第一阶段围绕“安静地活着”建立闭环。暂不把对话、云端长期记忆、追逐鼠标或窗口攀爬设为必需项，但保留它们在后续产品方向中。

美术母版可以是 3D，第一版运行时不必是完整实时 3D。全实时升级也应由交互需求和成本收益触发，而不是默认必须经历的阶段。

项目当前最值得消除的风险是：**目标美术质量、自然交互与常驻性能能否同时成立**。角色三视图和桌面技术样机可以分别准备，不必等完整角色资产做好才发现桌面集成不可行。
