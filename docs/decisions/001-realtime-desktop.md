# ADR 001：灵犀以真实实时 3D 为目标

日期：2026-09-11。状态：用户确认真实 3D 目标；具体运行时选型为待验证建议。此决策替代旧文档中“预渲染优先”的当前路线，旧方案保留作历史比较与离线预览用途。

## 决策

统一的 Blender 角色母版提供几何、纹理、骨骼、动作与 Groom；桌面端使用真实网格和骨骼实时渲染，实现连续注视、眼耳尾局部动作、换肤与动作混合。预渲染用于宣传、对照和资产预览，不能拿图片平面冒充最终角色。

macOS 首个技术验证建议：**AppKit 透明非激活 NSPanel + WKWebView + Three.js WebGL2 实时渲染**。设置 UI 可以后续使用 SwiftUI；跨平台时将窗口能力通过 `DesktopHost` 实现，Windows 可选 Tauri 壳。同一 GLB 与行为契约可复用，原生宿主不与角色代码混在一起。

先使用可预测的 WebGL2 路线测视觉与功耗；WebGPU 是经实机验证后的可选后端。如果材质质量、毛发排序或能耗达不到目标，第二候选是 AppKit + Metal 原生渲染，此时需承担毛发、动画和资产加载开发成本。不要把已有 Web 技术习惯当成强制限制。

## 桌面呈现

窗口边框关闭、背景透明、内容保持 alpha，支持置顶及全桌面策略但不抢焦点。按角色命中区域处理输入，透明区域穿透；拖动、隐藏、托盘退出始终可用。大小按屏幕像素决定 LOD。全屏应用、屏幕录制、锁屏与低电量可自动隐藏或降帧，具体行为由用户配置。

Apple 文档说明 NSWindow 承载窗口和事件，Metal 通过 CAMetalLayer 呈现；透明常驻窗口不能套用其“不透明全屏 direct-to-display”的性能结论。[Apple 窗口与 Metal](https://developer.apple.com/documentation/metal/managing-your-game-window-for-metal-in-macos)

Tauri macOS 透明窗口涉及其特定配置；不能默认所有平台都零成本兼容。[Tauri 配置](https://v2.tauri.app/reference/config/)

## 达到参考图真实度的资产要求

- 身体：连续可变形的四足拓扑，真实肩胛、脊椎和重心，轻度幼态比例。
- 眼睛：眼球、虹膜、瞳孔、角膜、眼睑闭合、泪线；高光随照明变化，避免把眼睛做成黑玻璃球。
- 毛发：Blender 离线母版用分区 Groom；运行时先比较细密 Hair Cards / shells 与局部高质量毛束。关键脸颊、耳缘、胸、尾保持轮廓。每种材质都需要实际导出验证。
- 动作：呼吸、眨眼、眼先于头的注视延迟、独立耳尾；基础姿态与局部动作分层混合，最短停留与冷却由行为系统管理。
- 灯光：柔和固定主光与填充，保留接触感，不读取用户桌面像素来假装物理环境照明。
- 皮肤：统一 rig、材质槽、花纹遮罩和 LOD 契约；体型变化超出兼容范围时用新 rig 版本。

不能承诺 `.blend` 中 Geometry Nodes Groom 原样变成 GLB。USD/GLB 的输出应按目标运行时实际支持制作，先做眼睛和一块毛发测试再扩展全身。

## 可复现实验与通过条件

1. 同一只猫、同机位和尺寸输出 Cycles 参考帧、实时桌面帧，记录差距。
2. 测试 256、384、512px 猫尺寸以及深浅杂乱桌面，连续转头、眨眼、呼吸与毛发边缘无明显跳变。
3. 测试透明区域操作底层应用、拖动、多屏缩放、不抢焦点和可靠退出。
4. 记录目标机 CPU、GPU、内存、帧时间和能耗，不能把百分比愿望当成实测。
5. 若目标毛发质量未达标，继续改资产或评估原生 Metal，不以“用户看不出来”替代视觉验收。

当前证据：Blender 5.2.1 和官方 MCP 已验证，设计工作场景已保存；**未完成成品角色和桌面渲染样机，尚无真实度或性能达标结论**。
