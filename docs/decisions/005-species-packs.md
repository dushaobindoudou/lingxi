# 决策 005：其他物种以「物种包」接入，统一的是意图，不是骨架

**状态**：已决定方向，2026-09-24。**未实现**，代码里没有任何物种包相关的改动。设计细节在
[`docs/24-species-pack-design.md`](../24-species-pack-design.md)。
**问题**：桌宠以后能不能换成狗、鸟、人、鱼？用什么办法支持，统一的接口放在哪一层？

---

## 决策一：先把猫做完，架构只留接缝

猫的造型（v5 look-dev）还没过关，现在做通用化等于给一个没定型的东西写抽象。
这一阶段只做两件几乎零成本的事：

1. Agent 只说意图、动作 id 从 `lingxi_capabilities` 拿——这一条已经做对了，不退回去。
2. 以后在 `apps/lingxi/src/anim/` 里**新写**的代码，按骨骼角色（头、脊柱链、四肢、尾巴链）
   引用节点，不再写 `'upperFL'` 这样的字面量。旧代码不专门重构。

## 决策二：统一的接口是「意图」，不是骨架

狗、鸟、人、鱼的身体结构根本不同，硬塞进同一副骨架只会让每个物种都别扭。
真正能共享的是**它想表达什么**：开心、接住你的坏情绪、注意到你、休息、一起庆祝。

所以统一放在两层：

- **对外**：Agent 的 `state` / `kind` / `mood` 词汇（[19](../19-agent-integration.md)）保持不变，与物种无关。
- **对内**：在「反应映射」和「具体动作」之间加一层封闭的**意图词汇表**。每个物种把意图映射成
  自己的动作：猫是踩奶、呼噜，狗是摇尾、转圈，鱼是吐泡泡。

物种之间不同的东西——骨架、运动方式、活动空间、五官、动作库、作息参数——全部装进一个
**物种包**，按同一份清单约定交付。

## 决策三：按身体结构分运动模块，而不是按物种

运动方式只有少数几种：四足、双足、飞行/跳跃、游动。猫和狗共用四足模块，只改步法参数。
新增一个物种，最好的情况是**只加数据**；新增一种身体结构，才需要写一个新的运动模块，并单独开一份决策记录。

## 决策四：第二个物种是狗

狗和猫的身体结构相同，最便宜，又最能检验接缝切得对不对。验收标准只有一条：
**加狗不需要改 director、renderer、life-engine 的任何一行，只加物种包和四足步法参数。**
做不到，说明接缝切错了，先修接缝，不做第三个物种。

鸟和人其次，鱼最后（没有腿、没有地面，活动空间和交互都要重新设计）。

## 决策五：记忆和关系属于这只伙伴，不属于物种

一只伙伴 = 物种包 + 皮肤 + 性格 + 记忆。延续 [决策 004](004-cat-friend.md)：
关系留在「这一只」身上。**同一只伙伴能不能换物种**是产品问题，本页不替用户决定，
记在设计文档的「未决问题」里。

## 什么时候该改主意

- 猫的造型批准、进入接入桌宠的阶段时，回到这里，按设计文档的迁移步骤 1 开始。
- 如果加狗的时候发现 director 或 renderer 必须改，说明意图层或活动空间抽象不对，先改本页。
- 如果有人提出「所有物种共用一副通用骨架」，先回到决策二。
