# 2026-10-09 · 托盘提醒与 Agent 集成审查

## 结论与证据

用户看到的托盘数字原本是活动表里等待／失败状态的数量，并无已读记录。查看主界面不会改变
这些状态，因此数字不消失；宿主未发会话结束事件时，旧行还会永久参与计数。
运行中的 `/activity` 确有 WorkBuddy 的旧会话等待行。测试
`tray_attention_clears_when_a_wait_has_been_read` 在原计数谓词上失败，修复后通过。

固定文案来自应用的回合结束兜底，以及默认反应表的等待句。
WorkBuddy 使用共享 Claude 形状适配器；它原本没传 Notification 的 echo，应用将重复提示当成新等待。
原 echo 的十分钟窗口又会重新刷新旧等待，导致长期提醒和已读复活。

## 本次实现

1. 已读存在活动行上，托盘只数 24 小时内未读的等待／失败／blocked。前台首页确认实际展示的
   六行快照；未读排在前面。回执以行 key 和事件 revision 校验，新事件不被旧回执消费。
   阅读不改变任务状态；点击托盘提醒直接到首页。衰减复用 perception 心跳，只在计数改变时更新原生菜单。
2. 同一等待的 Notification 不重复说、不续年龄；新的真实请求和继续运行仍正常更新。
   共享适配器传 echo，授权消息有工具名时传具体请求；schema 补齐 origin／echo。
3. 无内容的回合结束只更新状态。模型 summary、实际回复中的结果／问题优先；缺内容的等待／失败
   提醒带宿主来源和“请查看会话／错误详情”。不用完成态去猜用户目标已经达成。
4. Cursor hook 的 session 保持真实会话身份。MCP task 增加可选 session，允许模型报告与 hook
   对齐；未知时省略，不借用全局“最近活跃会话”。插件副本同步，宿主 skill 更新为实际行为。

## 各宿主的后续优化

| 宿主 | 当前入口与信息能力 | 优先改进 |
|---|---|---|
| Claude | 原始 hooks 有 session、权限请求、回复；CLI 自动带会话 | 保持作为基准；模型只补具体结果、mood 和 hooks 看不到的阻塞 |
| Codex | 原生 hooks／notify + CLI + MCP；CLI 有线程，MCP 可传 session | 会话级对齐优于按 agent 最近三分钟的报告兜底；继续守住 hooks／notify 单一路径 |
| WorkBuddy | 共享适配器保留 session、结果与 echo；CLI 身份需显式指定 | 核实宿主真实会话环境字段后再自动注入 CLI，补 SessionEnd 清行；额度守卫仍独立 |
| Cursor | hooks 只有生命周期，已补 session；无回复文本 | 依赖模型终态 summary；不把生命周期缺内容补成虚构结果；补 hook 脚本行为测试 |
| 豆包 | watcher 读本机日志，尝试截回复；包装器借短期 active-conversation 对齐 | 并发会话时全局 active-conversation 有误归属风险，应从当前任务工作目录确认会话；取不到则省略 |
| DSH | 任务语义通过动态工具描述传达；运行中的动态插件未自动随源码更新 | 有真实会话标识时携带 session；补工具行为测试，并单独补应用安装入口 |
| 通用 MCP | task 参数已有 taskId／summary／mood／可选 session | 用 schema 提供完整任务语义；不要要求模型额外 say 一遍，否则绕过 task 去重 |

## 下一步的统一方向

宿主只负责生命周期事实与真实来源，模型负责具体结论和情绪，应用统一管理已读、衰减、去重与表现。
不要让各插件各自维护未读账本或回来摘要，否则多宿主下会出现多个通知逻辑。

后续可增加真实 turnId，替换目前“同一 agent 的近期报告覆盖无 session hook”的时间窗推断；
同时为没有 SessionEnd 的宿主增加明确的陈旧状态展示。当前首页任务仍是内存快照，24 小时衰减
只退出提醒计数，不能当作持久任务档案。猫身上的未读点与单击回放应在这份状态模型上接入。
