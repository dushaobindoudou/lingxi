# 技术架构与验证

> 历史基线（2026-09-10）：产品现已命名「灵犀」，用户要求以真实实时 3D 为目标。最新决定见 [实时 3D 决策](decisions/001-realtime-desktop.md)、[品牌设计](08-brand-and-design-system.md)和[扩展架构](09-extension-architecture.md)。与新决定冲突的旧建议不再适用。

状态：候选技术设计；未创建应用、未执行运行时验证。官方资料核对日期：2026-09-10。

## 1. 模块边界

| 模块 | 负责 | 对外边界 |
| --- | --- | --- |
| Desktop Shell | 窗口、托盘、隐藏退出、屏幕坐标、系统生命周期 | 输出经过归一化的环境事件 |
| Cat Life Engine | 生活状态、候选评分、冷却、合法转移 | 请求语义行为，不依赖具体渲染技术 |
| Animation Director | 将行为转成当前资产支持的动作序列 | 管理入口出口、安全切出、完成与失败 |
| Renderer | 透明动画播放或实时模型呈现、局部命中区域 | 报告支持能力和播放事件 |
| Local Store | 版本化设置、位置、生活状态 | 可迁移、损坏可回退 |
| Optional AI Adapter | 摘要、意图校验、预算与超时 | 只能影响获准的高层倾向 |

渲染器应暴露能力，例如有限方向观察、是否支持自主移动、是否支持局部微动作。行为层不能请求不存在的能力。不要为了可替换性在 P0 先建设完整插件平台。

## 2. 渲染路线比较

| 路线 | 适合 | 主要约束 | 当前处理 |
| --- | --- | --- | --- |
| 固定角色离线预渲染，运行时播放 | 高质量毛发、有限机位、安静休息 | 存储与解码开销、动作接缝、方向数量 | P0 优先候选 |
| 简化模型实时 3D | 连续注视、独立眼耳尾、灵活位移 | 材质毛发开发、透明合成、功耗 | 制作小样作对照 |
| 预渲染身体叠加实时部件 | 局部可控且保留部分离线质感 | 遮挡、接缝、光照与视角匹配复杂 | 未经专门验证不采用 |

本项目建议将“混合”首先定义为**统一 3D 母版生产资产，运行时行为动态编排**。不要用同一个词同时承诺身体与部件的混合合成。后续选择全实时并非必然升级；如果预渲染已满足核心体验，可以长期保留。

## 3. 候选工具及已知边界

Tauri 为桌面壳候选，React 可用于设置界面，但动画循环不应依赖 React 每帧更新。透明序列路线不强制使用 Three.js 或 WebGPU。

Tauri 官方配置说明：macOS 透明窗口相关能力涉及 `macOSPrivateApi` 配置。是否采用及其对目标分发渠道的影响应在样机阶段核实，不能把跨平台透明窗口视为无需验证的开关。[Tauri 配置参考](https://v2.tauri.app/reference/config/)

Three.js 的 `WebGPURenderer` 默认尝试 WebGPU，并提供 WebGL 2 回退。该能力不能证明目标 Tauri WebView 中的透明、材质和动画都正常；必须在实际打包应用中测试。[Three.js 官方说明](https://threejs.org/manual/en/webgpurenderer)

Blender 到 GLB 的毛发、材质与动画导出仍列为工程验证项。本轮未成功读取当前 Blender 导出手册，因此不声称已核验具体版本支持范围。

## 4. 桌面共存的验证清单

首先制作最小透明窗口样机，确认：

- 可见猫区域接受交互，透明区域允许操作底层应用；窗口级穿透不能自动等同于逐像素命中。
- 不激活窗口也能显示猫；设置窗口与猫窗口的焦点行为分开验证。
- 猫区 hover、拖动和穿透切换不死锁；缺少全局输入权限时仍能通过托盘恢复和退出。
- 多屏、缩放、负坐标、显示器拔出后，位置被限制到可见工作区。
- 锁屏、休眠、恢复、全屏应用和桌面切换行为明确；MVP 可优先隐藏而非始终覆盖。
- 不把获取其他应用窗口边界或全局键鼠输入当作 Tauri 默认可用能力；按平台单独验证。

首版可以只用猫区域输入，无需记录键盘内容、窗口标题、屏幕或麦克风。后续感知只采集功能需要且用户开启的数据；云端 AI 默认不接收原始内容。系统拒绝权限时应减少能力而不是阻止基本陪伴。

## 5. 资产与性能预算

预渲染并不天然低内存。例如 512 × 512 的 RGBA 帧，30 fps、10 秒完全解码后占用约 300 MiB（不含额外缓存）；压缩文件大小不能代表运行时内存。因此需测试分段加载、帧缓存上限、按尺寸取资产和实际解码方式。

透明编码是否在目标 WebView 支持、是否硬件解码、alpha 边缘是否正确，都属于样机结论。P0 可先用短透明序列排除编码干扰，再评估正式交付格式。

原文 CPU <2%、GPU <5%、内存 <300 MB（理想 <200 MB）记录为**待测愿望预算**。不能作为跨机器统一保证。建议在 P0 指定最低目标设备后冻结验收口径：

| 条件 | 必须记录 |
| --- | --- |
| 设备 | 芯片、内存、OS、屏幕数量与缩放、电池或接电 |
| 软件 | 应用版本、WebView、渲染后端、资产版本 |
| 画面 | 猫像素尺寸、实际帧率、播放状态、运行时长 |
| CPU | 测量工具、整机/单核口径、应用及子进程总量 |
| GPU | 测量工具及利用率口径，不与其他平台直接横比 |
| 内存 | 应用与 WebView 等相关进程总量、峰值与稳定值 |
| 流畅度 | 帧间隔、卡顿、动作接缝；记录可复现样例 |
| 能耗 | 对照无猫基线的能耗、温升或风扇变化 |

建议预热后分别采样静息、连续互动和隐藏各 10 分钟，再检查长时间运行是否持续增长。静息和互动帧率按样片质量确定；隐藏或锁屏时暂停渲染和非必要决策。正式预算由测量结果与用户可接受度共同决定。

**现状（2026-10-08）。** 功耗分三档由 webview 的调度器决定（`apps/lingxi/src/main.ts` 的 power governor），
Rust 侧跟随（`PowerState`）：

| 状态 | 进入条件 | 渲染 | 后台 |
| --- | --- | --- | --- |
| 活跃 | 猫在动、有互动 | 每个 vsync | 光标移动时 60Hz，静止 1 秒后 20Hz |
| 静息 | 猫静止 10 秒无互动（一动当帧回到活跃） | 30fps，睡觉 20fps | 光标 10Hz |
| 停摆 | 熄屏、锁屏、屏保、睡眠、切换用户，或托盘隐藏 | 完全停止 | 所有线程挂起不唤醒，只剩 30 秒一次的对账兜底 |

"没人看得见"只认系统通知（`watch_system_presence`），不从 rAF 停顿推断——透明置顶窗口在看得见时也会被
系统降低合成优先级。渲染侧画布只包住猫（`fitCanvasToCat`），猫身一次绘制调用（`rig/merged-body.ts`），
两者的画面一致性由 `probe-fit.html` 检查。

## 6. 失败与恢复

资源加载失败回到可用待机或可操作的占位界面；LLM 超时不影响生活；状态文件损坏恢复默认；拖动或显示器改变后重新约束坐标；用户退出最高优先级。记录故障原因及资产版本，默认不记录敏感原始输入。
