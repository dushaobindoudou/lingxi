## 1. Bugs (sorted by impact)

### B1 · Memory and reminders are 403 for every published integrator — P0

`POST /memory` and `POST /reminders` go through `refuse_untrusted_write()`. The caller's identity **is read only from
the `X-Lingxi-Agent` request header** (`apps/lingxi/src-tauri/src/lib.rs:2303`; the comment explains why the body cannot be read:
a body can be consumed only once). Without that header the caller is `anonymous`, the tier takes the default `performer`,
`may_write_settings()` is false → **403**.

**And right now no client sends that header:**

| Client | Location | Headers it sends |
|---|---|---|
| `lingxi` CLI | `integrations/cli/lingxi:131` | Only `Authorization` + `Content-Type` |
| MCP server | `packages/mcp-server/src/bridge.mjs:281,288` | The same; identity is stuffed only into the body's `agent` field |
| DSH plugin | `lingxi_remember` in `integrations/hosts/dsh/lingxi-dsh-plugin.js` | The same |
| Claude hooks / Codex notify | Plain curl | These two endpoints are not involved |

Consequence: `lingxi remember` / `lingxi remind` / `lingxi_remember` / `lingxi_remind` /
DSH's `lingxi_remember` **never succeed even once**, unless the user manually promotes `anonymous` to `trusted`
— and the permission table in the main window lists only agent ids that have appeared, so `anonymous` may not be in the list.

The README homepage's claim "it can remember things about you, and remind you a little later" does not hold today.

Direction of the fix (pick one; do not do both):
- Clients add the `X-Lingxi-Agent` header (three places: the CLI, `bridge.mjs`, the DSH plugin), or
- The Rust side peeks an `agent` field before reading the body (that changes the consume order of `read_body_capped`).

**Regression check**: `lingxi remember "测试" moment` should return 200; in `lingxi agents`, that id's
call log should record `applied` rather than `denied`.

### B2 · The DSH plugin's `lingxi_remember` is still wrong even after B1 is fixed

`lingxi_remember` in `integrations/hosts/dsh/lingxi-dsh-plugin.js` is the only tool that **does not call**
`ensureIdentity(ctx)` before sending the request. The other four all call it. Even with the header added, the id `dsh`
may not be in the registry yet (the registry is purely in memory and is empty after an app restart), so the tier falls to the default.

### B3 · `accentText` is implemented and validated, but the README the app itself writes never mentions it

`parseBubbleStyle` already accepts `accentText` (`apps/lingxi/src/rig/custom-assets.ts:87`),
and `docs/19` lists it as one of the integration acceptance checks. But the
`assets/README.md` written into the asset directory at app startup (the template is the `## bubble.json` section of `custom-assets.ts`) **does not include this field** in its example.
A user who follows that README will never learn there is an emphasis color.

### B4 · Probe artifacts would be packaged into the `.app`

`apps/lingxi/public/.probe-sunhonglei/` (2 PNGs, 20 KB) is an uncommitted temporary probe artifact.
Vite copies the whole `public/` directory into `dist/` as-is, including directories whose names start with a dot, so it would enter the package.
The size is small, but it is not release content.

### ~~B5 · `dist/` is already in the repo~~ — withdrawn; this item does not hold

Misjudged on the first look. `apps/lingxi/dist/` is indeed on disk (4.8 MB), but `dist/` in `.gitignore:3` already excludes it.
`git ls-files apps/lingxi/dist` is empty — it is only a local build artifact and was never committed.
