## 问题与非常具体的处理方案

### 1. P0：侧卧过渡仍穿地，落定后后爪局部相交

**证据**：重新加载最终 R，逐帧扫描 SideLie 249–296。第 260 帧 LX_Body 最低 z=-44.81 mm；实际 Studio ground 顶面 z=-5.00 mm，即裸皮穿地 **39.81 mm**。第 284 帧已无同等穿地，但后爪局部表面有 **149 对相交面**。选择范围为绑定空间 z<75 mm 且 Paw+Toe 权重和>0.45，排除了上方小腿；相交数量是局部表面交叉证据，不是穿透深度。

最深点为身体网格顶点 19850，权重 RearPaw.L=50.7%、RearToe0.L=49.3%、Pelvis≈0.1%。因此这次穿地确实发生在左后爪/趾皮肤，不能继续归因于此前已基本修掉的“脚掌被骨盆权重拖拽”。

**原因判断**：完成帧的腕/踝位置靠固定高度与 `h_stack_dz=.065` 校准；动画过渡中身体滚转、目标插值和爪的变形表面没有共同的接触约束。下爪的掌面也没有随空间摆腿独立校正：已有最终 R 数据中下后爪掌面偏离水平约 81°，上爪约 18°。

**处理**：

1. 把目标从“腕/踝点 + 一个平面角”改为“掌面接触点 + 完整朝向 + 肘/膝弯曲方向”；先以掌面目标反算腕/踝目标，再求解两骨链。
2. 保留空间求解，但用完整旋转补偿父骨滚转和外展，不能只在上腿叠一段旋转后仍用单个 `paw_ang` 代表脚掌朝向。
3. 侧卧下爪目标贴地；上爪目标取下爪**实际变形后的爪背表面**，沿该表面的法线留 1–3 mm 接触余量。删除固定 65 mm 作为最终接触保证的做法。
4. 分开“胸腹下降、骨盆侧转、后爪叠放”的时间曲线；整个过渡逐帧检查接触，必要时校正目标并重新求解。不要只把 Root 整体抬高。
5. 保留并记录目标误差、离面误差、超出可达范围；达不到的帧应报错，不能 `_` 丢掉。

**验收**：全帧裸皮距真实地面≥-2 mm；接触帧掌面与地面/下爪距离 0–3 mm；上下爪局部不相交；腕/踝目标误差≤2 mm；超出可达范围≤1 mm。以上是下一轮工程阈值，不是宣称当前已经达到。

### 2. P0：蜷睡没有“下巴由双前爪支撑”的关系

**证据**：最终 R 第 350 帧右前掌垫最低 z=132.65 mm，左前掌垫最低 z=23.79 mm。头部最低点与两只前爪局部皮肤在水平面最近距离约 297 / 342 mm；这是“头部最低点”代理值，不能当作精确下巴解剖标记，但足以结合渲染排除托下巴关系。原来的参考差距探针也复现了同方向偏差。

**处理**：

1. Sleep 接入空间求解，并去掉求解完成后的 `add_FL/FR/HL/HR` 硬摆。
2. 在下巴实际皮肤、左右前掌接触区设置显式标记，使用变形后的标记计算接触。不能以 Head 骨点或整颗头的最低点作为最终下巴接触判断。
3. 先将双前爪并排落地，再让胸、颈、头一起收回到两爪后半部；两爪间距按实际爪宽设定。现在头在远端，不能通过单独降低头部高度解决水平位置错误。
4. 身体蜷曲由 Pelvis/Loin/Spine 分担，胸腔给前腿留空间。先完成无毛侧视与俯视轮廓，再恢复毛发。

**验收**：下巴投影落在两前掌后半部的支撑区域内，接触距离 0–3 mm；双前爪掌面接近地面；无头—爪穿插；俯视能辨认左右两爪。若保留别的睡姿，也必须明确其支撑位置，不能继续称它“前爪托下巴”。

### 3. P1：舔爪求解器的 1 mm 接触没有兑现到成品

**证据**：构建日志 `LICK_SOLVE` 报接触 1.0 mm，但超出可达范围 4.9 mm、腕部实际旋转约 85.1°，高于代码配置的 1.0 rad 惩罚阈值。重新测第 537 帧，舌头到实际主肉垫最近 **4.71 mm**，到四个豆豆约 56–70 mm。检测到的爪局部与头部相交面为 0，所以不能据旧描述认定这张成品已撞穿口鼻。

**原因判断**：求解仍使用平面链、近似椭球肉垫和稀疏表面点；最终肉垫已改成贴面皮肤。目标约束是带权惩罚，允许违反腕角/可达性来换取低总分。日志里的 `facing` 只打印，没有参与目标函数；因此未保证掌面正对舌头。

**处理**：

1. 使用成品形变后的肉垫网格和舌头表面求接触，不再以旧椭球代理决定最终接触。
2. Lick 接入空间腿部求解，让肩胛、上臂外展、前臂旋转和腕部共同把掌面送到嘴边；优先增加肩部活动，不先放宽手腕限制。
3. 把可达性、穿插和腕部范围设为硬约束；不能把罚分非零的结果当“已解决”。当前 1.0 rad 是实现阈值，仍需与目标风格及关节轴定义一起校验，不能直接当生理上限。
4. 将掌面朝向加入约束。先固定舔哪一片肉垫，再设计“抬爪→轻转头→舔舐→回爪”的分段动作；接触段舌头伸出，回收段先退舌再落爪。
5. 在烘焙动作后重新扫描实际网格，避免求解状态和最终 NLA 状态不一致。

**验收**：至少连续几个舔舐接触帧舌—垫距离 0–2 mm；没有舌穿皮、爪穿口鼻；腕部不超设定范围；可达性合格；前视和侧视都能看出舔的是爪而非遮脸。

### 4. P1：爪形更连续，但正面过宽、侧面仍像鼓包

**视觉证据**：Q→R 消除了独立趾球和腕部环棱，方向正确。但 R 四趾瓣依然等节奏排开，爪宽在交接中约为腿柱 1.27 倍；侧面爪背是大圆顶。毛发的弯曲亮线又强化了这个圆顶。不能用只含 Pad/Bean/Claw 的高度去判断连续爪皮高度，也不能把含小腿的包围盒当爪高。

**处理**：保留元球，先做无毛局部形状 A/B。初始候选范围：爪体 z 半径 33→26–29 mm；趾瓣 z 半径 32→25–28 mm；趾中心高度同步下降以保持爪底位置。爪体 x 半径 74→67–70 mm、趾间距 35→30–32 mm；外侧两趾略收小/后收，做浅弧而非四个等大的瓣。所有数值是待渲染检验的候选，不能直接当已验证修复值。

元球相互融合后的尺寸会偏离单个元素半径，必须量实际表面。爪背和趾前缘设置独立短毛区，先比 4–7 mm 的贴面毛；长毛在腕部逐渐过渡，不要把整个身体下方的长毛层无区别延伸到趾尖。观察裸皮与带毛同机位对照，区分造型鼓包和毛发增厚。

**验收**：四趾可辨但属于同一爪；严格侧视轮廓低而平顺；肉垫边缘贴面；屈腕后趾缝不裂、肉垫不浮起。保持现有连续表面，不退回独立四球。

### 5. P1：闭嘴改善了线条，胡须垫体积问题还未解决

**证据**：R 缩短人中并把 ω 加宽、渐细，但头部仍由两个中心相距 62 mm、x 半径 52 mm 的口鼻球合并而来；重叠区域很大。唇线仍是独立带厚度曲线转换的网格。正面能看到线，却看不清“左右胡须垫鼓起—中线凹入—下唇少量露出”的体积关系。哈欠下缘变圆有改善，但上沿和两角仍需三分之四视角复审。

**处理**：

1. 先隐藏唇线与毛，雕出左右胡须垫和中线浅沟。候选：中心 x=±31→±36–40 mm，x 半径 52→44–48 mm，前表面增加 2–4 mm 局部体积；控制外侧边界，避免整张脸变胖。
2. 唇口做成实际皮肤边界，保留极薄的阴影/颜色辅助；嘴角嵌回皮肤。不要靠继续加粗 ω 获得可读性。
3. 鼻、人中、上唇边界、下颌皮肤、牙齿与口腔共同对齐；更换胡须垫后重新测闭嘴牙尖是否藏在皮肤后。
4. 张口使用连续唇边的形变与口角补形，保持中央人中凹口和两侧弧面；避免只有正面开口轮廓好看、侧面口角拉成长方口。

**验收**：无毛灰材下也能读出双胡须垫，闭嘴无露牙；正常观看距离嘴缝可见而非一条贴上去的线；张口无口角破洞/折痕。先判断几何，再调毛流和材质。

### 6. P1：验收工具本身有错误口径

- `v6_ref_gap.py` 把掌面倾角直接写成常数 5.9°；其“forearm mid”实际取骨骼起点；爪形尺寸只量独立附件。这些指标需要修正后才能作为通过条件。
- `v6_lying_audit.py` 的 85 mm 体表邻域会混入小腿，且每个 clip 的“最低一次高度”不能判断过渡每帧均合格。
- 大多数旧报告假定地面 z=0，实际本文件地面顶面在 -5 mm。必须明确报告的坐标口径。
- `knobs.txt` 追加的旧默认值说明还写着 JAW_YAWN=.62、GAPE_W=1.2，与 R 当前源码 .72 / 1.0 不一致。下一轮保存源码 hash、实际解析参数、模型 hash、渲染帧与相机，防止版本混用。

## 骨骼与连接关系的判断

你的怀疑有依据：已证实的是**控制链没有完整表达接触关系**，空间求解未覆盖 Sleep/Lick，爪的朝向没有被完整约束。尚没有证据证明必须推翻现有骨骼父子层级。

后腿目前 `RearPaw` 同时承担跖段与脚掌控制，后续可以在踝—跖段—掌面之间增加独立掌面控制，必要时加一根掌骨，并重分对应蒙皮。但应先通过上述接触目标验证需求；增加骨骼数量本身不会修复目标插值、超范围或穿插。

建议执行顺序：**接触验收与版本记录 → 侧卧全程 → 蜷睡支撑 → 舔爪 → 爪形与胡须垫**。前三项先做无毛灰模，确认全帧结果后再制作正式带毛渲染。
