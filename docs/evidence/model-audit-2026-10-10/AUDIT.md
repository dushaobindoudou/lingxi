# 灵犀当前猫咪模型审计与修正方案

审计日期：2026-10-10。结论：躺姿确实涉及骨骼控制，但主要证据指向**折腿方向、腕部朝向、接触约束和姿态组合**。当前父子层级没有发现前后腿挂错、左右骨骼错接等结构错误。爪子缺少几何细节；嘴巴的实体骨骼被隐藏，实际表现是平面贴图切换。

本次完成审计、可复现探针、12 格实际渲染图及独立诊断候选；没有替换桌面应用的模型或修改其设置。

- 正在运行的桌宠通过 CLI 确认为 `deepseek-whale`「深寻蓝鲸」，`scale=0.25`、`camera=auto`。

## 3. 骨骼连接：保留主链，明确关节与接触点

建议保留这几条父子链：

```text
hipC → spine3 → spine2 → spine1 → neck2 → neck1 → head
                            ├→ scapL → upperFL → lowerFL → pawFL
                            └→ scapR → upperFR → lowerFR → pawFR
hipC ├→ thighL → shinL → footL → pawBL
     └→ thighR → shinR → footR → pawBR
head → jaw → tongue
```

`upperF` 的原点是肩关节，`lowerF` 的原点是肘关节，`pawF` 原点可继续承担腕关节。后腿的 `foot` 原点对应跗关节 / 飞节区域，不应因为它“反向折”就把父子连接换掉。关节位置应与可见肢体两端对齐，不应放在盒体中心。前后肢关节对应关系可参考[伊利诺伊大学猫影像解剖图谱](https://vetmed.illinois.edu/imaging_anatomy/feline/forelimb/elbow/ex01/elbo01-f%20.html)，本报告中的姿态数值是项目调试起点，不是兽医学运动范围。

每只爪新增三个不绘制的局部标记：`soleContact`（承重点）、`padCenter`（肉垫中心）、`toeTip`（趾尖）。现有前爪盒体的底面中心是局部 `(0,-1.232,0.4)`，不是 `pawFL` 的 `(0,0,0)`。一旦改变爪几何，应从最终盒体 / 网格计算这些标记，避免硬编码旧尺寸。

再新增 `chestSupport`、`bellySupport`、左右 `flankSupport`，定义不同姿态的支撑部位。头部保留 `jawHinge` / `tongueTip` 标记以协调张嘴和舔爪。

## 4. 躺姿的具体改法

### 4.1 先纠正折腿，再写接触求解

当前香箱前腿的累积角度为：肩胛 0.1；上臂 -1.16；前臂 0.74；脚掌 0.60 rad。上臂把肘推向头部方向，后续腕部缺少收拢控制。

修正目标：肘部朝躯干后方折，前臂向胸底回收，腕部独立决定脚掌是承重、放松还是揣手。给前腿两骨 IK 指定肘部方向 / pole，不能让求解器在两个镜像解之间自由跳。后腿保留大腿、小腿、跖段的三段关系，分别控制膝部和飞节方向。

下表是已渲染的诊断起点，左右对称。单位是相对于 rest pose 的弧度或位置偏移，不能直接当作最终动作库发布：

| 通道 | 当前香箱 | 诊断候选 |
|---|---:|---:|
| scapL/R.position.y | 0 | +1.0 |
| upperFL/FR.rotation.x | -1.10 | +1.55 |
| lowerFL/FR.rotation.x | +1.70 | -2.80 |
| pawFL/FR.rotation.x | 0 | +1.25 |
| thighL/R.rotation.x | -1.30 | -1.15 |
| shinL/R.rotation.x | +1.25 | +1.85 |
| footL/R.rotation.x | -0.40 | -1.40 |
| pawBL/BR.rotation.x | 0 | +0.70 |

后腿外展保持原值 ±0.22。候选胸底降至 **0.916 voxel**，前爪倾角≈0；前爪仍离地 **0.545 voxel**，腿与身体仍有不理想的穿插。说明无需先换父子树就能降低悬空，但这套 FK 参数仍需被接触求解和可见轮廓约束替代。

### 4.2 将一个全局落地规则改成分姿态支撑约束

在 `body-controller.ts` 将动作偏移应用与接触求解拆开。`-box.min.y` 只保留为防止明显穿地的最后兜底；它不能作为姿态正确的唯一指标。

建议新建 `anim/contact.ts`，按以下模式求解：

| 模式 | 必须控制的支撑 | 其他目标 |
|---|---|---|
| stand | 四个 soleContact | 保持掌底水平，肩胛高度与骨盆高度共同适配腿长 |
| walk | 当帧处于 stance 的 soleContact | swing 爪正常抬起；保留现有步态的距离驱动 |
| loaf | chestSupport / bellySupport + 允许接触的腿侧面 | 前爪收到胸部轮廓内，后脚放在髋外侧；不要求所有爪平铺承重 |
| prone | 胸腹、前爪 | 前肢伸向前，头可休息在前爪或地面附近 |
| side | 下侧 flankSupport、下侧肢体 | 上侧腿自然放松，不能与下侧腿完全对称；头颈按地面独立调整 |

当前 `side-nap` 不应仅靠 `root.rotation.z`。新建独立侧卧姿态：指定侧别→下侧肢体收拢→躯干落在侧腹→上侧肢体松弛→头颈补偿。整体滚转可用约 1.45–1.57 rad 作为构图起点，最终由接触与轮廓决定，不把 90° 当硬性验收。

建议求解顺序：**rest → idle / gait → clip 主姿态 → 身体柔动、表情头部补偿 → 末端位置与朝向约束 → 支撑接触求解 → 最终防穿地检查 → 桌面位置 / heading 放置**。当前 renderer 在 `bodyController.apply` 后仍修改脊柱和头部，尤其头部承重或侧卧时需要在这些变换后重新检查接触。相关动态误差尚未单独量化。

验收起点：站姿每只爪支撑误差 ≤0.15 voxel；香箱胸底距地 ≤1.0 voxel（进一步美术验收目标为 0.2–0.5）；承重脚掌法线偏离目标 ≤5°；动作中支撑点不会突然切换；香箱前爪藏入胸部轮廓，而非简单露出两个前置鞋底。阈值是建议的项目验收指标，需要同时看正面、侧面和斜侧效果。

### 4.3 睡眠采用进入、保持、退出三阶段

新增持久姿态层 `basePose=sleep`，由生命引擎状态决定。一次性动作库仍按原契约首尾归零。

- `sleep-enter`：约 1.0–1.5 秒，从站姿转到蜷卧支撑状态。
- `sleep-hold`：持续保持基础姿态；呼吸和偶尔尾尖变化作为小幅附加层，不再重播完整 `curled-sleep`。
- `sleep-exit`：醒来时退出基础姿态，再衔接伸展与站起。

修改 `main.ts:750` 的反复 `playAction('curled-sleep')`，并为 director 增加持久姿态接口。验收至少连续 60 秒睡眠，无周期性站起；醒来只执行一次退出过程。

## 5. 爪子的具体改法

第一阶段不必添加大量趾骨。保留现有 `paw` 节点，在其下增加一个掌体、四个可辨识的承重趾团、一个主掌垫和四个趾垫。隐藏的小爪尖只在伸爪 / 抓挠时露出。趾 / 掌垫的分组用于视觉表达，可参考[加州大学托管的猫项目解剖资料](https://ucanr.edu/sites/default/files/2024-07/400276.pdf)；下列尺寸是方块风格设计草案。

以当前前爪为基准，可先尝试：掌体 size=(2.35,1.05,1.9)，offset=(0,-0.52,0.10)；四个趾团 size=(0.52,0.72,1.05)，x 分别为 -0.87/-0.29/+0.29/+0.87，y=-0.66、z=1.02；主掌垫约 (1.0,0.08,0.85)，小趾垫约 (0.36,0.06,0.40)，都贴在对应底面外侧。先做倒角或分级方块轮廓，不把风格切成写实球体。

腕部求解改成位置 + 朝向：承重时对齐地面法线；揣手时朝胸下折；舔爪时将 `padCenter` 指向 `tongueTip`，同时给肘部 pole 限制。不要 CCD 完成后用固定 `paw.rotation.x=-0.7*weight` 覆盖任务姿态。建议验收舔舐点位置误差 ≤0.2 voxel、肉垫朝向误差 ≤10°。

`mergeBody` 可继续用于这些刚性小部件，保持单个合并材质；脚掌几何改变后重新计算接触和框选范围。近景确认趾团和主掌垫可辨识，常用桌面尺寸确认轮廓有改善，再决定是否需要独立趾关节。

## 6. 嘴巴的具体改法

### 6.1 几何

保留 `head → jaw → tongue` 主链。拆开头部下前方完整封闭的方块区域，做真实口缝；增加左右口鼻垫、下唇 / 下颌壳、口腔内壁和独立舌头。现有 `jaw` 盒体不能只恢复可见，因为完整 head 方块仍会挡住它。

在 `renderer.ts` 区分“由贴图替代的眼眉 / 胡须节点”和“需要绘制的口鼻节点”，解除 `jaw`、`tongue` 隐藏。面部贴图保留眼睛、眉毛及必要纹理；去掉与 3D 嘴重复的黑椭圆和舌头图案。下颌铰链应放在头部后下方，不能把前端嘴角当旋转中心。

### 6.2 连续控制

在 director 输出连续 `mouthOpen`、`tongueOut` 值，沿用现有 `face.open` / `face.tongue` 动作通道；枚举嘴型只提供默认值。将连续值传入面部控制器。

初始角度范围可尝试喵叫下颌张开约 0–0.35 rad、哈欠约 0–0.65 rad。当前坐标 +z 向前、+y 向上，前伸下颌绕 x 正向旋转会降低前端；最终应根据新网格铰链验证旋转符号。舌头从口腔内部前移，根部留在嘴内，不能只贴在脸前。

短期若只做平面改进，也应让黑色口形的高度、下唇和舌头长度随权重连续变化，去掉 0.3 / 0.55 阈值跳变；这只能改善正面，不能解决侧面缺少口腔的问题。

验收：0、0.25、0.5、0.75、1 五档开口连续；正面 / 45° / 侧面均能看出嘴缝与下颌变化；闭口不露黑腔；舌头不穿上唇 / 下唇；舔爪能建立舌尖与掌垫的接触。

## 7. 柔性轮廓与碰撞验证

当前 draw-call 合并不等于柔性蒙皮。短期在肩、肘、髋、飞节添加小型过渡壳并收紧远端盒体，允许明确的小范围相邻重叠；中期若要柔软弯曲，需要连续网格与跨关节混合权重。保持方块审美也可以通过多段小截面弯曲表达，不必把整体做成圆滑写实猫。

修改 `probe-clips.ts`：只对白名单中的相邻关节接缝允许重叠，给每对指定容许深度；取消“任何祖先后代都豁免”。AABB 用作快速筛查，确认盒体碰撞使用 OBB，并对原本允许的接缝单独计量。Three.js 的 [OBB 官方接口](https://threejs.org/docs/pages/OBB.html)提供局部盒体世界变换和 `intersectsOBB`；它返回相交布尔值，深度需另用 SAT 或几何计算，不能把布尔值当穿透量。

增加接触点高度、支撑切换、爪朝向、舌尖距离、睡眠周期回站姿几类检查。新增爪 / 口鼻后不要原样复用旧 UV 布局；现有 PNG 皮肤需保持 v1 路径或显式迁移，新增布局使用独立版本 ID。首阶段姿态 / 接触修复可以保持 v1 主骨架及皮肤兼容。

## 8. 实施顺序与交付验收

1. 修复基础站姿四爪接触、前腿折叠和腕部目标，单独验收香箱；通过后再做俯卧、侧卧、蜷卧。
2. 修复持续睡眠，保留动作库的首尾归零约定。
3. 补脚掌几何和舔爪的朝向 / 接触控制。
4. 重建下前脸口腔区域，将连续嘴部控制接到下颌与舌头。
5. 最后处理关节过渡与 UV 迁移，用多角度完整时间轴回归。
