## 1. 需求转译

| # | 原始需求 | 产品转译 | 现状 |
| --- | --- | --- | --- |
| 1 | 接入 Codex / Claude / DSH | 三个一等公民"室友"，折叠面板各自管理，一键接入，可断开 | ◐ 通道已核实（docs/09）；UI 待建；首发 Claude |
| 2 | 感知 agent 状态并反应 | 任务事件 → 归一化 → 节制的猫侧反应 + 任务流 | ◐ 契约/测试已在；无渲染通路与 UI |
| 3 | 提供 skill 和 MCP | 设置页内的 MCP server + 工具清单（风险分级）+ skill 指引 | ⬜ 待建；HTTP 桥是前身 |
| 4 | 情绪价值；agent 能更新宠物配置 | agent 在权限档位内**直接**写白名单字段（无审批），全程调用日志 | ⬜ 提案 |
| 5 | 独立 LLM 按活动做简单响应 | 规则层常驻 + 可选 LLM 层（OpenAI 兼容配置），输入白名单 | ◐ 成长占位公式已在 |

**定位：主界面是用户与猫、猫与 agent 三方关系的仪表盘。猫在桌面上的呈现是"结果"，主界面是"原因"的编辑器。**

## 2. 非目标

- 不做 agent 的遥控器/聊天窗；**对 agent 任务只观察**：不批准、不拒绝、不取消、不代答（延续 `TaskObserver` 契约"只读"边界）。
- 不做审批/确认流：宠物侧配置由权限档位 + 字段白名单约束，无卡片、无远程批准。
- 不上传屏幕内容/图像给 LLM；感知只有统计与状态。
- 不做账号云同步，所有数据本机。

## 3. 用户与使用时刻

1. **配好就忘**（99% 时间）：重要状态在托盘/猫侧可感知，主界面不是必经之路。
2. **偶尔查看**（每天几次 <30 秒）：谁在干活、猫干嘛呢 → 首页 3 秒扫读。
3. **出事排查**（每周几次）：连接/权限/调用有可读日志与原因，不是"未知错误"。

## 5. 全局组件

**状态徽章** `● 已连接 / ◐ 空闲 / ○ 未连接 / ⚠ 异常`（颜色语义全文一致）；**权限开关**（toggle + 影响面副标题）；**空状态**（每页必定义，引导下一步）；**Toast**（右下 3s，仅确认类；错误用内联红字）。v1 的"审批卡片"组件随决策 1 删除。

## 6. 逐页规格

### 6.1 首页（此刻）

目的：3 秒回答"猫怎么样、谁在干活"。

```
┌─ 猫 ──────────────┐ ┌─ Agent ────────────┐
│ [缩略渲染/状态插画] │ │ Claude ◐ 空闲  ⚠1  │  ⚠= 有任务等待用户/失败
│ 状态: 陪工作中      │ │ Codex  ● 运行任务 2 │
│ 位置: 右下 · 工作模式│ │ DSH    ○ 未连接     │
│ 心情: 放松 (0.7)   │ │ —— 最新任务 ————    │
│ 精力 ▓▓▓░ 72%      │ │ ✓ 重构 renderer.ts  │
│ 成长 Lv.3 ▓▓░░░    │ │ ⋯ 跑测试 suite…     │
└───────────────────┘ └────────────────────┘
┌─ 今天 ────────────────────────────────────┐
│ 互动 12 次 · 拖拽 2 · 被避让 5 · 专注 3h12m │
└──────────────────────────────────────────┘
[ 逗猫模式 ] [ 找回猫咪 ]                      ← 快捷操作
```

- 数据源：`GET /perception` 同源快照 + TaskStore snapshot，2s 轮询，页面不可见时暂停。
- Agent 卡点击 → 跳到接入页并展开对应折叠面板；任务行点击 → 展开 ≤240 字摘要（契约已定）。
- ⚠ 徽章只表意"有任务需要用户去 agent 侧处理"，**主界面不提供任何操作**（决策 10）。

### 6.2 Agent 接入（折叠 + 一键接入）

每平台一个手风琴分区，默认全部折叠、展开一个：

```
┌ ▸ Claude Code ──────── ○ 未连接 · 首发适配 ┐
├ ▸ Codex ────────────── ○ 未连接           │
├ ▸ DeepSeek Harness ─── ○ 未连接           │
└───────────────────────────────────────────┘
```

**展开后的 Claude 分区（首发）：**

```
┌ ▾ Claude Code ──────────────── ◐ 空闲 ────┐
│ [ 一键接入 ]   （已接入时显示 [断开] [重新检测]）│
│ 接入方式: Hooks 自动合并写入 ~/.claude/settings.json │
│           （写入前自动备份，可一键回退；不会覆盖已有 hooks）│
│ 权限档位: (👁 观察) (💬 建议) (🎮 操作) (⚙ 配置)  默认 👁 │
│ 今日任务: 4 完成 · 1 失败 · 0 等待你        │
│ ▾ 任务流（可滚动，失败/等待置顶）              │
└───────────────────────────────────────────┘
```

- **一键接入**按平台落地（均先自动检测、失败降级为"复制配置手动粘贴"）：
  - Claude：把 `UserPromptSubmit`/`Stop`/`StopFailure` hooks 片段**合并**进用户 settings.json（备份 + 回退），收到首个事件徽章转绿；
  - Codex：引导启用 app-server 事件订阅（`thread/status/changed`、`turn/started`、`turn/completed`）；
  - DSH：检测 `dsh-acp` 并建立 `dsh/sessions/watch`。
- 权限档位每平台独立：👁 观察（只读任务事件）→ 💬 建议（AIIntent 移动/模式建议）→ 🎮 操作（MCP 全部低风险工具）→ ⚙ 配置（**直接**写白名单字段，见 §9）。
- 边界继承 docs/09：断连只标过期不推断完成；摘要 ≤240 字；原始 prompt/工具参数不进事件；观察者无批准/执行/取消能力。

## 7. 猫侧反应设计

沿用 docs/09 节制原则：默认安静、事件合并、冷却、重要状态辅以文字（托盘/主界面），不只靠表情。

| 触发 | 猫侧 | 主界面/托盘侧 |
| --- | --- | --- |
| 任务完成 | `soft_glance`：轻微抬头 + 小庆祝 | 任务流行首 ✓；免打扰概念已删除，动作恒开（受全局模式约束） |
| 任务失败 | `attention_mark`：歪头 + 耳后压 | 托盘 tooltip"有任务失败"；任务流置顶 |
| 等待用户 | 走到屏幕下缘安静坐下 | 任务流置顶 + 首页 ⚠ 徽章 + 托盘 tooltip（仅提醒，无操作） |
| 长任务运行 | 每步安静，偶尔看一眼屏幕方向 | Agent 卡"运行中 n" |
| 断连/过期 | 无动作 | 徽章 ○ + 过期标记（不推断完成） |

## 9. 配置写入边界（替代 v1 审批流，依据决策 1/10）

不做审批卡片与远程批准。信任模型改为**权限档位 × 字段白名单 × 调用日志**：

```
Agent (MCP write_settings, 携带字段+值)
  → Rust 校验: schema ✓ → 该 agent 权限档位含 ⚙配置 ✓ → 字段在白名单 ✓ → 值经 sanitize ✓
  → 直接落盘 PersistedSettings + 广播生效（与托盘/主界面同一 TrayState 路径）
  → 调用日志记一行（谁、何时、改了什么、旧值→新值）
  任何一步不过 → 拒绝 + 回执原因 + 日志记录
```

- 字段白名单（第一版）：`interactionMode`、`scale`、人格 traits、行为预设档位。**身份字段（名字/性格一句话）默认锁定为用户专有**，不在白名单——猫的名字是用户与猫的，不授权 agent 修改。
- 白名单外的字段（如皮肤）第一版拒绝，回执明确"该字段不支持 agent 修改"。
- 用户随时可在设置页关闭某 agent 的 ⚙ 配置档位；关闭即时生效。
- 频控：同一 agent 每分钟 ≤10 次写入，超出拒绝——防失控脚本刷配置。
