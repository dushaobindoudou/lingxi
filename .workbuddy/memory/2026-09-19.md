**这次读代码新确认的关键事实（#3 的修法因此很便宜）**：
`CapabilitiesState.latest`（lib.rs:563-570）在启动时由渲染器 `report_capabilities` 上报并缓存了完整动作/表情清单，
`GET /capabilities` 直接读它。所以 Rust 侧**不需要复制词表**就能校验 action/expression。
注意初始值是 `json!({})`（lib.rs:1835）—— webview 上报前是空表，此时必须降级为转发，不能误杀合法请求。

**#2 的一个补充证据**：`TaskEvent` 的 schema 本来就带 `platform` / `source`，
`react_to_task_event` 把它们压成 `(expression, action, line)` 三元组后就丢了。
所以 #1 和 #2 其实共享同一份数据缺失 —— 归属信息在归一化时就有了，只是没往下传。

**原因**：① MCP 还没被信任 → WorkBuddy 里 skill 的自动化路径未激活；② 上一轮我只写了文件和文档，
**从未真的驱动过猫**（主因）；③ 动作保持时间短 + 有延迟，容易错过。

**实测结果（全部经 `POST /control` 直达 HTTP 桥，不依赖 MCP 信任）**

1. 驱动前按 skill 规矩查 `perception`：`petState=wander`、`toy=null`、`activeAgent=none`、`idleMs=239s` → 可驱动。
2. `{"expression":"好奇","action":"notice-you","say":"喵～连上啦"}` → `ok:true`，applied 三项，
   `applied` 里带 `(forwarded)`。**猫有反应。**
3. **假成功已复现（问题 #3 证据）**：
   - `{"action":"this-action-does-not-exist","expression":"这个表情也不存在"}` → `ok:true`、rejected 为空、猫什么都没做。
   - 对照 `{"perform":"nope"}` → **HTTP 400** + `perform: unknown performance "nope" (see GET /capabilities)`。
   证明确实只有 `action`/`expression` 两条路径漏了校验。

**发现的新行为（重要，已补进 skill）**：**动作在猫走路时会被推迟到它停下才播。**
连续采样 `paw-wave`：t+0.6s 仍 `wander`/`action=null` → **t+1.2s 变 `idle` 才开始播** → t+4.8s 播完（正好 4s 时长）恢复 `wander`。
后果：发完立刻回读 `action` 可能是 `null`，**不代表失败**；agent 若因此重发会把动作排乱。
`idleDurationMsRange` 是 1.8–5s，所以走动中的等待可能比这更久。
→ 已写入 `references/interface.md`，并在 `SKILL.md` 反应映射处加了警告。

**用户可直接自测的命令**（不依赖 WorkBuddy 与 MCP）：
```bash
curl -s -X POST http://127.0.0.1:47811/control -H 'Content-Type: application/json' \
  -d '{"expression":"开心","action":"paw-wave","say":"看到我了吧～","holdMs":15000}'
```
`holdMs` 要放大到 10–20 秒才容易看见；默认 4000 太短。

### 最严重的一条：#7 `/intent` 无校验 → 猫消失

```bash
curl -X POST 127.0.0.1:47811/intent -d '{"targetPoint":{}}'   # → {"ok":true}
curl 127.0.0.1:47811/perception    # → petPosition {"x":null,"y":null}, petState "ai_directed"
```
猫从桌面消失。根因链（读代码确认）：
1. `main.ts:340` 只判 `if (targetPoint)`，空对象是 truthy，直接透传；
2. `life-engine:727-734` 的 `clamp(targetPoint.x, minX(), maxX())` 是**虚假防御** ——
   `clamp` 是 `Math.min(Math.max(v,min),max)`，`Math.max(undefined,24)` = NaN，clamp 透传 NaN；
3. `heading` 与 `position` 同时 NaN，`moveToward` 里 `atan2(dest.y - NaN, ...)` 持续产出 NaN
   → **NaN 自我维持**。

**恢复不可靠（实测）**：`{"resetPosition":true}` 返回 ok+applied，`main.ts:350` 也确实监听了
`reset-position` 并调用 `engine.resetPosition()`，但**之后连续采样 24 秒位置仍非法**。
`resetPosition()`（index.mjs:790-800）重置了引擎侧变量，**没重置 `heading`，也没触及渲染层平滑状态**。
约 10 分钟后猫**自行恢复**（位置回到左边缘 x≈32），但**恢复触发点无法确定** ——
`/perception` 不暴露 heading/表情，也没有事件日志，无法还原现场。
