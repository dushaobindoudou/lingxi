**根因（对后续迭代最重要）**：
1. `fur_color()` 里算了条纹相位 `s/m1/m2` 但混色只用了与位置无关的 strength 遮罩——**条纹从未参与混色**（尾巴生效是因为 tail 分支用了 s）。任何"改了对比度没反应"的问题先查这个模式。

5. 毛无弯曲 → 毛毡感；groom 加 per-strand 正弦波 + 长度层次(.55~1.3)。

**新 fur_color 设计（世界坐标，猫面向 -Y，z 向上）**：躯干 sin(x*115+warp) 纵向纹（z<.19 淡出、腹白袜子）、额头 sin(x*150)+中线 exp 高斯 + 顶部 .63 淡出、脸颊横纹、嘴周白(限 |x|<.062)、眉点两个高斯白点、尾巴 sin(y*150) 环纹。dark (.225,.14,.082) / light (.58,.46,.33) / white (.92,.87,.76)。

## 50G 内存事件：根因、修复与验证（10:20-11:20）

**用户观察**：Blender 跑到 25G→50G 内存。要求深挖。

**根因（真凶）**：我在 per-strand 杂色里写的广播 bug——
`colors(np4,3) * np.repeat(jit(n,1,1),4,axis=0)(4n,1,1)` → 对齐成 **(4n,4n,3)**，
standard 档 n=8 万 → 320000²×3 个 float64 ≈ 天文数字 → OOM killer（exit 137）。
教训：**numpy repeat 一个 (n,1,1) 到 per-point 标量时，多出的尾轴会让乘法广播成 n×n**。
正确写法 jit=(n,1) → repeat → (4n,1)。任何"改个参数就 OOM"先查广播维度。

**排除项（有数据）**：
- 不是逐帧泄漏：15 个姿势连续渲染 RSS 0.772→0.824GB（+52MB，14 次比较仅 1 次微增）。
- 稳态很轻：打开 36MB blend（含 73.6 万毛发顶点）= 0.587GB；单帧渲染 +231MB。
- `native_fur` 里源 strand mesh **不是泄漏**——渲染曲线每帧从它（带 Armature 蒙皮）采样位置，
  它是变形源（`deformation_source`），删了毛发就不跟动画。差点误删，教训：删对象前先查依赖。

**已落地的修复**：
1. jit 广播 bug 修复（真凶）。
2. `groom` 弃用 `from_pydata`（会把每个 strand 点变成 Python tuple，百万级），改裸 API
   `vertices.add + foreach_set`——10 万根实测仅 12MB。
3. `bind` 权重写入从 O(unique×n)（每个权重值全表 np.where）改 argsort 分组 O(n log n)。
4. `LINGXI_QUALITY=preview/standard/hero` 毛量分级，**默认 standard=单层 guard**；
   hero（双层底绒）必须显式开启——它把所有成本 ×2。
5. build-report 现在记录 `quality` 与 `peak_rss_gb`，内存回归可被机器发现。

**验证**：standard 档（183,981 根毛 + 900px/48samples 渲染）完整构建 **峰值 1.156GB**（/usr/bin/time 实测），此前 50G。

**诊断工具（入库，可复用）**：`scripts/blender/diagnose_v5_memory.py`（只读资产账本，
macOS 下 task_info 取当前 RSS 而非 ru_maxrss 峰值）、`diagnose_fur_cost.py`（小规模测每千根成本再外推）、
`diagnose_render_loop.py`（15 连渲染判"是否逐帧累积"）。注意 ru_maxrss 是峰值不回落，测"释放收益"必须用当前 RSS。

**遗留**：条纹渲染比 10:06 版淡（attribute 数据对比完好 0.18↔0.87，嫌疑在 denoise 平滑/毛发覆盖的感知差异），
下次可在材质里给 stripe 加一点饱和度或降低 denoise 强度。并发 agent 同时在改 build 脚本（lidmat 眼睑改进），合并时注意。

## 毛发"看不见"事件与修复（13:05-13:15）

用户反馈截图看不出任何毛发。两层原因：

1. **管线顺序坑**：`build_lingxi_v5.py` 结尾会 save_as_mainfile **覆盖** blend，从而抹掉
   `native_fur_lingxi_v5.py` 上一轮生成的 hair curves。只跑 build 不跑 native_fur → blend 里
   CURVES 对象为 0 → 渲染根本没有毛。**build 之后必须跑 native_fur**（sh 里是对的，单独跑就会踩）。
   排查方法：数 `bpy.data.hair_curves` / type=='CURVES' 的对象。
2. **参数太小**：即使有曲线也几乎不可见。实测"隐藏全部毛发"对照渲染：毛发只改变 3.44% 像素、
   高频细节 1.14x、轮廓覆盖率无变化（86.15% vs 86.18%）。
   原因：毛长 13mm（猫身长 ~700mm，占 2%），半径 .00042（900px 图上不到半像素），
   且一根毛 4 个点同色 → 无体积感。

修复：body/head/tail 毛长 .013/.0085/.013 → .024/.015/.022；
RADII guard .00042→.00078（under .00030→.00045）；新增 root→tip 渐变
`np.tile([.80,.92,1.06,1.22], n)[:,None]`（暗根 + 亮尖，这是"毛感"的关键）。
结果：毛发影响像素 3.44% → **9.01%**，细节能量 1.14x → 1.20x。轮廓仍几乎不变（86.32 vs 86.35），
说明绒毛主要提升表面质感而非轮廓毛边 —— 若想要更明显的轮廓绒毛，需给轮廓处单独加长/加密。

**量化毛发可见度的可复用方法**：渲染 hide 全部 LX_Fur*/LX_RenderFur* 的对照图，与有毛图比
"改变像素占比 + 高频梯度能量 + 轮廓覆盖率"。比肉眼判断可靠（本会话后期看不了图，全靠这个指标）。

峰值内存保持安全：build 1.33GB、native_fur ~1.7GB。

## "白猫"事件：长毛版渲染整只发白、条纹消失（14:00-15:10）

用户要求对标 logo 参考图 `assets/characters/lingxi/reference/turnaround-v1.png` 做长毛蓬松奶猫。
毛长/配色/蓬松物理改完后渲染出来是**一只纯白猫，EV 压到 -2.5 也不变**。四个原因层层叠加，
每一个都遮住下一个（本会话后半段看不了图，全靠量化指标 + 隔离渲染定位）：

1. **毛源网格裸奔（最致命）**：8 个 `LX_Fur_*` strand mesh 没有材质，Cycles 用**默认白材质**
   渲染成一层白绒，把条纹皮肤和有色毛发全埋了。它们只是 GN 变形源，本不该出现在渲染里。
   修：`groom()` 里创建即 `ob.hide_render=True`（native_fur 里也补一次，兼容旧 blend）。
2. **颜色空间错了一整档半**：调色板是**显示空间**数值（dark .47 / light .80），写进 FLOAT_COLOR
   attribute 后被当**线性**读 → 整体淡 1.5~2 档，条纹对比被压平。修：build 里加 `srgb_lin()`
   （真 sRGB 传递函数），在两处落点（皮肤 CORNER attribute、毛发 POINT attribute）统一转换。
3. **Principled Hair BSDF 的 COLOR 参数化对浅色毛几乎不吸收**：29 万根半透明毛多次散射成
   **奶白纱**。T（TT lobe）从 1.0 压到 0.15 都无效——因为白纱来自密集散射而非透射参数。
   换不透明 **Principled BSDF + coat_color 属性**（rough .72 / sheen .25）→ 绒感 + 花纹回来了。
   参考图的治愈奶猫本来就是绒毛玩质感，这个替换反而更对。
4. **补光把暗纹填平**：Fill 40 / Bounce 22 → 对比只有 56（参考图 74）；改 30/15 → 63~72。

**对照实验结果（同一帧，320px）**：皮肤单独渲染 = 花纹/配色全对；曲线单独渲染 = 近乎透明的幽灵；
普通哑光棕色材质 = 米棕可见 → 由此确认着色器是问题所在，而不是配色数据。

⚠️ **本轮最大的一次误判**：我在毛源网格还可见时做了"常量棕色"对照实验，结论"Color 输入无效"
是**被白绒污染的错误结论**，让我绕了一大圈。教训：**做着色器对照实验前先隔离掉所有无关对象**。

### Blender 5.2 的三个 API 陷阱（本轮全踩到）
- `node.inputs['Transmission']` **按 identifier 查找**，与 UI 标签不一致（毛发 Transmission 的
  identifier 是 `'TT lobe'`，两个名字都 KeyError）。必须用按标签遍历的 helper：`sock(node,name)`。
- `n is not node` **恒为真**（RNA 每次给新包装对象）→ 想保留某个节点时会被一起删掉；要用 `!=`。
- 节点被 `remove` 后其引用失效（outputs 变空）→ 后面访问会抛 StopIteration。
- 另：`material.use_nodes = True` 在 5.2 已废弃且**不再自动创建 Principled 节点**（6.0 移除）。
