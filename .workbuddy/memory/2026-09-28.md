# 第二段：面部比例（用户：`base 16` 很接近了，眼睛位置比例/嘴巴大小不对，怀疑面部骨骼）

## 先说约束

**这个会话读不了图片**（Read 返回 "the current model does not support images"）。
之前几轮面部迭代靠的是眼睛看叠加图；这条断了之后，全部改成**只出数字**。
这不是降级 —— 毛脸本来也看不准比例（3 cm 毛把眼鼻嘴全糊住），数字反而更硬。

## 基准只能用瞳距 E

参考图 `lingxi-ref-face-closeup.png` 是**把耳朵裁掉**的紧裁切 → 头的宽度在照片里量不到
（mask 就是整帧）。所以"眼睛是否太宽"这类问题在照片上**不可判**。
唯一跨构图/镜头/裁切/物种都成立的尺子是 **E = 瞳距**，而它本身就是眼睛大小的定义量，
于是有了一条**内部一致性检查**：瞳距 1.0E、单眼可见跨度 0.48E → 两眼内角之间只有
0.52E 的缝 → 参考图 0.31E 的鼻子正嵌在里面。**不需要参考图的头宽。**

## 新工具（都不需要看图）

| 工具 | 作用 |

| `v6_face_landmarks.py` | 用**距离变换峰值**找瞳孔（同时给出圆心与半径，不依赖眼睑/毛的假设），再以 E 归一化报告鼻/嘴 |

参考图实测（`v6_face_shape.py` 的 `REFERENCE`，脚本自测自，参考列读 0.0%）：
瞳径 0.194 / 鼻宽 0.311 / 鼻高 0.160 / 鼻心 dy **+0.320** / 嘴宽 0.288 / 嘴心 dy **+0.630** /
鼻镜粉峰 Δ115（Δ = R − max(G,B)）。dy 一律是**瞳孔线以下**。

## 两个把结论带反的测量错误（重要）

1. **绝对阈值**：第一版用「绝对粉色阈值」在参考图上找鼻镜，抓到的是**失焦背景**，
   于是得出"鼻子几乎宽一倍"→ 把 `V6_NOSE_W` 收到 0.62 → **把本来接近的鼻子改小了一半**
   （0.196E → 0.148E）。改成「以鼻轴自身峰值的相对比例切」之后，参考实测 0.311E。
2. **只看行宽不看实心度**：用"最宽的一行"找鼻子，在参考图上得到 0.63E 的"鼻子"——
   那是一圈散落的粉色像素（**实心度 13%**），不是鼻镜（实心度 100%）。
   → 每行必须同时报 **跨度 + 实心度 + 像素数**，只有实心行才有投票权。

## 取景：把相机钉在眼对上（本轮最贵的一个坑）

`v6_render_views.py` 原本按目标物件**包围盒**算相机距离 → 改鼻子/下颌/毛量都会改头盒尺寸
→ 相机前后移动 → **瞳距（一切比例的分母）跟着变**。曾有一轮完全没碰眼睛，瞳距却从
174 px 变成 127 px（−27%），所有面部数字一起漂，"鼻子大了还是小了"根本分不清。

修法：面部视图钉在 `Eye.L`/`Eye.R` 骨的中点上，令瞳距恒为 `V6_FACE_E_PX`（默认 220 px）；
量的时候用 `v6_face_shape.py --e-px 220`，**不要再检测它**。残余检测误差实测
3.7%（裸脸）/ 16%（毛脸：眼周暗毛把暗区重心外移）—— 足以把毛脸结论整体拉偏一成。

同时给渲染脚本加 `V6_BALD=1`（把毛整层摘出渲染，打**基础几何**的脸；取景仍按带毛包围盒算，
所以裸脸和毛脸同一构图）和 `V6_HIDE=前缀,...`。

## 面部旋钮已写进脚本默认值（不再是命令行临时值）

`build_lingxi_v5.py` 里每个默认值都附了测量依据：

- `V6_EYE_R=.84` —— 瞳径/E 对上参考（原始 .039 确实偏大）
- `V6_NOSE_W=1.155` / `V6_NOSE_H=1.0` / `V6_NOSE_D=1.35` —— 鼻镜宽高深
- `V6_NOSE_DZ=−.008775` m、`V6_MOUTH_DZ=−.0216` m —— 鼻子/嘴整体下移
- `V6_MOUTH_W=.49` —— 嘴宽回到 ≈ 一个鼻镜宽
- `V6_MUZZLE_GROW=.008` m —— **口鼻部向下生长**（见下）
- `V6_HEAD_SX=1.06` / `V6_HEAD_SZ=.95` / `V6_EAR=.82` —— 上一轮视觉比对值，一并固化

⚠️ **`V6_MOUTH_DZ` 必须同时作用于** `LX_MouthCavity` / `LX_MouthFloor` / `LX_Tongue` /
`LX_Tooth` / 下唇 / 人中。只挪唇线不挪口腔袋，闭嘴时粉色会从新唇线**上方**露出来。
牙的位置也从硬编码 `.017/.014` 改成 `MOUTH_W` 的比例，否则嘴一收窄牙就挂到唇外。

### 这就是用户怀疑的"面部骨骼"

参考图的嘴比我们低 **0.08E ≈ 10.9 mm**。但下移唇线到下移后的高度时，
两个口鼻球（`MuzzleL/R`，z 半径 .040）**在中线不再相交** → 下巴皮肤会出现一个 ~2.6 mm 的缺口。
也就是说：**口鼻部的体积不够深，装不下幼猫那么低的嘴**。
解法不是把嘴挪回去，而是 `V6_MUZZLE_GROW`：口鼻球**向下生长**、顶边固定不动
（`z_c = .462−g`，`r_z = .040+g` → 顶边恒为 .502，底边从 .422 降到 .406）。
g=.008 时唇线离口鼻部下缘还有 **21.8 mm** 余量，中线也真正相交。

副作用：`jaw_share` 的区域随唇线下移而收缩（下颌骨驱动的面部变少），
张口类动作（Yawn/Bite）的下唇摆动范围会变。**改这个值要复查动作。**

- 渲染大致保 Δ（58 → 峰值 77）→ **是贴图本身只有一半饱和度**

  由 `make_skin_textures.py` 缩放后烘焙 → 校正写在 `ALBEDO_SATURATION`（`nose_skin.png: 1.85`），
