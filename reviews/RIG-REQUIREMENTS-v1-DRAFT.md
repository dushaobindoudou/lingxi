## 1. 运行方式的硬要求（决定骨架怎么组织）

1. **表情和身体分层**：任何动作上能套任何表情（方块猫就是这么用的）。脸部控制必须是**运行时可单独设置**的形态键 / 脸部骨，不能烘焙进动作片段；动作片段里不写脸部通道（眨眼、张嘴等由表情层或动作的「脸部轨」驱动）。
2. **实时解算**：步态（按里程）、转身、头和眼看向指针在应用里算。腿、头颈、眼的骨链要能在应用里用同一套解析解（二段 IK + 爪角 + 现在的 Foot）求，和 Blender 离线求解一致。
3. **导出预算**：three.js / glTF。骨骼数、同时生效的形态键数、文件体积要有上限（codex 批次 8 查）。毛在应用里是壳层毛，形态键只放皮肤网格；「炸毛」做成壳层毛的运行时参数（长度 / 竖立），不加骨。

## 4. 由此得出的 v1 增补（待 codex 调研后定稿）

**骨（新增）**：每耳加耳尖 1 节；舌加 1–2 节；前臂扭转辅助骨 ×2（必要时小腿 ×2）；眼睑若改骨驱动则用现有 Lid 骨。其余用现有骨，接上权重和驱动（Nose、Whisker、Eye、Lid）。

**自由度 / 求解（不加骨）**：三维腿部求解（髋外展外旋、肩外展内收、膝 / 肘朝向、爪尖内外八）；躯干扭转分配（仰卧、打滚、侧身理毛、转身）；端坐、香箱、仰卧、挠耳、洗脸的目标姿势。

**形态键（皮肤，运行时可设）**：上睑开合 L/R、下睑上推 L/R、笑眼弧 L/R、瞳孔缩放 L/R、眉内抬 / 外抬 / 内压 L/R、嘴角上 / 下 L/R、上唇抬 L/R、下唇下拉、嘴型 o、皱鼻、鼻翼、舌勺形；关节修正（肘、膝、跗、颈前屈、仰卧腹部）。已有：Breath、LieSpread、FlankThigh、SitHaunch、Blink、Squint、Tongue Up/Out、Claw Extend。

**材质 / 应用参数**：虹膜爱心 / 闪亮 / 含泪；炸毛、炸尾（壳层毛长度 / 竖立）。

**导出接口**：一份「控制名清单」——表情层（形态键 + 脸部骨）、注视（头 / 眼）、实时腿 IK 所需的骨名和静止数据，给应用侧对接。
