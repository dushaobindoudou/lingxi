# 给 Claude 的猫科角色制作研究：电影与游戏怎样获得可信的卧倒、跑跳

调研日期：2026-10-10。本文只提供研究和实施建议，没有修改任何模型。以下「公开证据」来自制作公司、开发者或软件官方；「建议」是面向当前 Blender 项目的工程推导，不代表这些公司的内部骨架结构。

## 先确定制作方向

电影级猫科的可信感来自骨架、肌肉体积、皮肤、动作参考和反复镜头审查的共同作用。不能把身体问题全部归因于骨骼数量，也不能用毛发遮住灰模的结构错误。建议先实现能在灰模下正确卧倒、跑跳的解剖驱动绑定，再处理体积与皮肤，最后恢复毛发。

目前没有拿到电影内部 rig、关节轴参数或权重文件。下述资料不能作为「MPC 用了某个数量的脊柱骨」「Stray 某个肩胛控制器这样连接」的证明。

## 五项可以核验的制作证据

### 1. MPC《狮子王》Scar：软组织需要骨架支撑，动作仍需人工制作

**公开证据**：MPC 说明建模参考设计稿与狮子照片；骨架、肌肉和皮肤流程协同开发。其软组织与骨架发生碰撞，以保持解剖和体积。Scar 动画采用手工关键帧，并研究大量真实动物视频。[MPC：The Lion King — Scar](https://www.mpcvfx.com/en/showreels/the-lion-king-scar/)

**对 Claude 的建议**：骨头控制位置和转轴；胸腔、骨盆、四肢肌肉代理负责体积；皮肤承担连续形变。卧倒时不可仅压缩整个躯干网格来贴地，应该先摆好胸腔和骨盆，再局部修正软组织受压。动作关键帧必须依据真实视频的接触与时序。

**局限**：来源没有公开骨数、局部轴、权重、求解器参数。不能把狮子的体型和惯性直接复制给家猫。

### 2. Wētā《丛林奇航》Proxima：准确骨架 → 肌肉 → 皮肤

**公开证据**：Wētā 明确说明 CG 美洲豹 Proxima 使用手动动画，参考真实美洲豹及家养动物视频；以准确骨架为基础，向外建立肌肉和皮肤，以得到运动中的自然下垂与晃动。[Wētā：Our Work on Jungle Cruise](https://www.wetafx.co.nz/articles/jungle-cruise)

**对 Claude 的建议**：把猫科结构转成三层可独立检查的 Blender 集合：骨架关节、低分辨率体积代理、最终皮肤。肩部滑动、大腿体积、腹部松软组织分别测试。体积代理用于理解、碰撞或形变参考，无需第一轮就部署完整物理肌肉系统。

**局限**：官方页面未公开其具体绑定节点或肌肉拓扑。美洲豹是结构参考，家猫实际动作和比例应优先使用家猫视频。

### 3. BlueTwelve《Stray》：真实跑跳视频和过渡精修比单帧姿势更关键

**公开证据**：开发者介绍无毛猫 Oscar 为动画师提供跳跃、跑步视频参考；动画师 Miko 与程序员 Rémi 对基本移动、跳跃和过渡反复精调。[BlueTwelve 开发者：Getting to know Stray’s leading feline](https://blog.playstation.com/?p=367025)

**对 Claude 的建议**：采用短毛/无毛猫视频观察关节和体表运动，用家猫完整动作匹配「预备 → 承重/蹬伸 → 离地 → 着地 → 恢复」。不要只调到生成图对应的极端姿势就结束；需要检查前后几帧如何进出该姿势。

**局限**：《Stray》是独立游戏，不能称其为 3A 制作案例；文章未公开骨架层级、IK/FK 实现、肌肉模拟或动画是否全部手工制作。不得把网络上的所谓「Stray 猫动捕视频」当作本项目制作证据。

### 4. Ubisoft ZooBuilder：3A 工作室关注真实视频到四足动作，但这是研究公开资料

**公开证据**：Ubisoft 2020 年介绍 ZooBuilder 利用四足视频估计姿态并输出 FBX；开发依赖已有关键帧合成数据，公告当时描述可处理美洲狮视频，并提及 Far Cry 野生动物需求。[Ubisoft：ZooBuilder at SCA 2020](https://www.ubisoft.com/en-us/company/careers/locations/articles/ubisoft-china-ai-data-lab-to-unveil-ai-driven-project-zoobuilder-at-sca-2020-showcase)

**对 Claude 的建议**：真实视频可作为关键帧或二维关节点标注来源。先人工标注脚底接触、肩/髋位置、躯干方向与动作阶段，再决定是否需要自动估计。生成的单张图片不具备视频里的时序信息。

**局限**：研究展示不等于证实某个 Far Cry 成品中部署了该技术，更不能推出当前 3A 游戏普遍使用某种统一猫科骨架。不要为本项目优先引入姿态估计工具，其遮挡、深度歧义仍需人工核对。

### 5. SideFX 官方肌肉工作流：多层形变和模拟可分阶段，而不是一次全部开启

**公开证据**：官方 Vellum 工作流以动画骨表面驱动肌肉，再处理组织；精细皮肤层是可选步骤，结果再转移到高分辨率表面。其连接包括肌肉端点、肌肉对骨骼和肌肉之间的约束。[SideFX：Muscles and tissue Vellum workflow](https://www.sidefx.com/docs/houdini/muscles/workflowvellum.html)

**对 Claude 的建议**：借用分层思路。先保证确定性的骨架动画与体积，再为肩胛、肘、髋、蜷卧腹部等局部制作校正形变；仅在这些结果仍无法满足镜头时评估物理组织模拟。不要把随机摆动或整体缩放当作肌肉系统。

**局限**：这是 Houdini 官方通用工作流，不证明上述电影用了这套特定 Vellum 节点；也不是必须迁移 Houdini 的建议。

## 具体落到 Blender 的实现顺序

以下均为本项目建议，不能反向引用为公司的内部做法。

### 第 1 步：建立可对照的骨架与体积图

先提交正面、侧面和俯视图；画出肩胛、肱骨、桡尺骨、腕/掌/趾链，以及骨盆、股骨、胫腓骨、跗/跖/趾链。明确关节中心、旋转方向和蒙皮区域，不能仅凭当前表面球体中心布骨。

胸腔和骨盆作为相对稳定体积，腰腹承担较明显的弯曲；颈部必须具有连续的运动及皮肤过渡。前肢肩胛的平移/旋转与上臂运动分开；后肢的跗关节、跖段和足底方向分开。最终的骨数由功能验证决定，不把「更多骨」当作验收指标。

### 第 2 步：先做六个灰模压力姿势

| 姿势 | 首要观察 | 必须避免 |
| --- | --- | --- |
| 站立 | 肩/髋位置、四肢折线、掌跖段与足底关系 | 用人类直立腿结构替代猫的趾行动物结构 |
| 腹卧 | 胸腹承托、肘和腕折叠、后肢收拢 | 四脚贴地但躯干悬浮；胸腔整体压扁 |
| 侧卧 | 胸腔和骨盆滚转、两侧肢体不同接触 | 完整站姿直接绕整体 Root 旋转 |
| 蜷卧 | 脊柱侧弯、骨盆与胸腔相对朝向、头颈收拢 | 单一腰骨急折或颈部裂缝 |
| 起跳预备 | 后肢屈曲与体重转移、前肢配合 | 四足同时机械下蹲而无动作意图 |
| 跑步收拢/伸展 | 脊柱与骨盆节奏、四足接触事件 | 用 Walk 提速冒充 Run；每一帧锁住四脚 |

动作差异须由家猫视频核对。表格中的运动描述是工作方向，不是为所有跳跃、所有跑步规定唯一顺序。

### 第 3 步：权重与校正独立于动作审查

先用纯色显示各骨控制区域，逐个转动关节，确认皮肤确实跟随。颈部没有有效颈骨权重、肩部被胸骨完全锁死、整只后足受单一跗段控制，都不能通过调整 IK 目标补救。

对每个压力姿势检查关节外侧体积和内侧折叠；在已经合理的骨架和权重上使用局部校正形状。Blender 官方确认 Shape Key 可以通过关键帧或 Driver 控制。[Blender：Shape Keys Panel](https://docs.blender.org/manual/id/5.1/animation/shape_keys/shape_keys_panel.html)

Armature 的 Preserve Volume 可用于比较关节旋转造成的体积损失，但官方也说明极端旋转处可能出现不连续。它不能修复错误关节位置或替代权重与解剖设计。[Blender：Armature Modifier](https://docs.blender.org/manual/en/latest/modeling/modifiers/deform/armature.html)

建议将 ShoulderFold、ElbowFold、HipFold、AbdomenCurl 等校正按局部关节或姿势组合驱动，并测试从零到最大值连续过渡。不要把某个动作帧号作为全局校正唯一依据，也不要通过一次整体软组织压缩改变所有姿势的体型。

### 第 4 步：动作先做 Blocking，再做连续性

每个动作先标注真实视频的阶段和接触事件，再制作粗关键帧。卧倒需要支撑转移与胸/髋下落过程；跳跃需要前后肢发力与根轨迹相协调；跑步需要明确步态、速度和步长，并处理左右前后相位。

IK 用于支撑足接触或短暂固定，FK 用于便于设计摆动/腾空姿态；转换时保持世界位置连续。控制脚落地不等于求解整个身体：胸腔、骨盆、脊柱和肩胛也要共同调整。不要为了清除某个膝或爪的穿地统一抬高 Root，导致整只猫离地。

### 第 5 步：生成图、真实参考与最终渲染分三栏验证

第一栏是 Codex 生成图，验证用户想要的剪影、气质和可见接触关系；第二栏是真实家猫视频关键帧，核对可实现的关节组合与动作阶段；第三栏是同视角 Blender 灰模/最终毛发渲染。

先匹配相机、地平面和尺度，再比较。单张生成图无法确定遮挡的关节与景深关系；如图中姿势与真实解剖冲突，以真实猫结构为基础，并在对照图注中指出调整。多视角下应仍然是一只连续、有体积的猫，而不是仅一个镜头吻合。

## Claude 每轮需要交付的证据

- 一个动作、一项主要结构问题为一轮；写出修改的关节、权重区域和预期行为，保留独立版本。
- 同镜头的参考/修改前/修改后图，以及纯灰模正侧俯三视图；细节问题另加肩、颈、腕和跗段局部图。
- 整个动作视频，至少包含开始、关键姿态、结束与相邻动作过渡；不要只选好看的单帧。
- 足底接触时段、明显穿插位置、身体支撑位置记录；验收包含视觉与接触，不以「爪的 Z 值在范围内」独立判定姿态正确。
- 确认皮肤和毛发获得相同基础形变；先通过皮肤审查，再开启毛发细节。

## 研究结论与边界

公开电影制作资料支持「解剖骨架 → 体积/肌肉 → 皮肤 → 毛发」的制作思路，公开游戏资料强调真实参考与动作过渡精修。对当前项目最可落实的是分层绑定、灰模压力姿势、局部校正和完整动作验证。

本文没有提供真实家猫关节活动范围的数值，不能用作兽医学 ROM 表，也没有公开公司的完整内部 rig。若 Claude 需要特定关节轴和生理活动范围，应继续查阅家猫解剖及运动学原始研究，而不能从作品画面猜出数值。
